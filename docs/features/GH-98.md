# GH-98 — Translate the SPEC.md headers used for pulling the UI fields

Delivery record for work package GH-98. Ticket: GH-98 "Translate the SPEC.md
headers used for pulling the UI fields" (branch `feature/korbat/gh-98`, start
commit `7f91855`).

## What changed

The project assistant (Projektassistent, feature F9) assembles a project's
`SPEC.md` from the Description fields and reads the text back into those
fields by matching the exact `##` section headings it wrote. Those headings
were German, so only German-header files round-tripped. The section headings
are now fixed English, independent of the UI language and of the language
entered into the boxes:

| Step id | Old heading | New heading |
|---|---|---|
| `ziel` | `Produktziel` | `Product goal` |
| `nutzer` | `Zielgruppe und Nutzung` | `Audience and use` |
| `umfang` | `Funktionsumfang` | `Functional scope` |
| `nicht_umfang` | `Nicht im Umfang` | `Out of scope` |
| `umgebung` | `Zielumgebung` | `Target environment` |
| `qualitaet` | `Qualität und Abnahme` | `Quality and acceptance` |
| `entscheidungen` | `Decisions Locked` | `Locked decisions` |
| `offene_fragen` | `Offene Fragen` | `Open questions` |

The wording follows this repository's own `SPEC.md` English headings where a
counterpart exists (`Product goal`, `Audience and use`, `Functional scope`,
`Out of scope`, `Target environment`, `Quality and acceptance`, `Locked
decisions`); `Open questions` follows the established UI translation, as the
repo `SPEC.md` has no counterpart. Files whose `SPEC.md` already uses exactly
these headings — including this repository's own — are pulled back into the
boxes; files with the old German headings are no longer matched (accepted
consequence of the ticket; no migration logic was added).

**No other logic changed.** In `bin/vibe_guide.py` only the eight
`STEPS[*]["heading"]` values changed; `_sections`, `_set_section`,
`_new_spec`, `state` and `apply` all key off `entry["heading"]`. The German
step titles shown in the assistant UI (`STEPS[*]["title"]`) are unchanged, so
the German UI and the localized display (including the `nova-project.js`
title mapping) behave exactly as before. In `bin/web/app.js`, the three
`GUIDE_TEXT` title translations that diverged from the new file headings were
aligned (`Target group and usage` → `Audience and use`, `Feature scope` →
`Functional scope`, `Decisions locked` → `Locked decisions`) so that in the
English UI the step title equals the exact section heading in the file —
otherwise users would be tempted to "correct" the file heading to match the
box, which would break pulling.

**Living documentation.** `docs/features/F9.md` (Projektassistent) now states
that the UI step titles stay as they are while `SPEC.md` always receives the
eight fixed English headings and that exactly these headings are read back.
`docs/import-manifest.json` records the new size/hash of
`bin/vibe_guide.py` and `bin/web/app.js` plus the change entry.
