# GH-108 — UI adjustments in the project detail

Ticket: GH-108 „UI Anpassungen Project Detail“ (branch `feature/m0p/gh-108`,
start commit `b3e02092`). The package changes the Nova project detail only;
the classic interface, the ticket store schema, and the runner are untouched.

## What changed

**Header (`nv-hero`).** `Start working` (`[data-nv-run-start]`) starts disabled
and is enabled by the existing `/api/run-state` poll only when no run is
active; its handler also guards against a click while disabled. `Check` and
`Full verification` moved into a collapsed `details[data-nv-more-actions]`
menu with a `More actions` summary; both keep their existing hooks
(`data-nv-action="verify"`, `data-nv-verify="full"`). `Add package`, `Report
bug`, and `Give feedback` moved out of the Work panel into the hero actions
row, so they are present on every tab. The old `nv-work-actions` row was
removed.

**Work view.** Quick filter chips form their own row above the search field;
the search wrapper is content-sized (`flex: 0 1 20rem`, capped at `24rem`)
instead of full width and still wraps on narrow screens. The existing `Show
done` toggle moved directly to the right of the search input inside
`[data-nv-filter-bar]`, keeping its `data-nv-work-hide-done` hook, count,
`aria-pressed` state, and wiring.

**Ticket sidebar.** Form fields inside `[data-nv-ticket-form]` now use the
full sidebar width (the general `32rem` cap no longer applies there). In
detail view the description is rendered by the existing DOM-only Markdown
renderer from `nova-settings.js` into
`[data-nv-ticket-description]`, so headings, line breaks, lists and code
blocks are formatted safely without `innerHTML`. The wrapper deliberately
does **not** use `.nv-ticket-desc`, which clips card text to `7.5rem`, so
long descriptions stay fully visible. If the renderer is unavailable, plain
text remains as fallback.

**In Progress controls.** `Continue` on in-progress cards is disabled while
`/api/sessions` reports a running project session (`running`, or a session
entry in `starting`/`running`); the existing run poll keeps the disabled
state current, and the click handler guards it. In-progress tickets can be
returned to `draft` or `open` from card buttons, by drag-and-drop from the
In Progress column, and from the detail sidebar state select. `blocked`,
`waiting-merge` and `done` remain runner-owned; the backend continues to
accept only `draft`/`open` targets and keeps done tickets protected.

**i18n and manifest.** Four new labels were added in English and German
(`Weitere Aktionen`, `Ein Lauf ist bereits aktiv`, `Startet die Arbeit am
Projekt`, `Eine Sitzung läuft bereits`). `docs/import-manifest.json` has
refreshed hashes for the three changed `bin/web` files and a GH-108 change
entry.

## Scope decision

GH-82 had removed user-facing state controls for `in-progress` tickets. This
ticket explicitly supersedes that UI restriction for the *source* state
`in-progress` only: users may move such a ticket back to `draft`/`open`, but
may not set `in-progress`, `blocked`, `waiting-merge`, or `done` from the web
interface. Autonomous mode was active, so the coordinating agent made this
decision from the ticket wording and SPEC.md; it is reflected in the living
docs and reviewed in the package.

## Post-review correction (round 1)

Independent review found one Medium defect: the in-progress detail panel still
showed the `data-nv-runner-state-notice` pill ("Zustand wird vom Läufer
gesetzt") next to the new draft/open state select, contradicting ticket item
7. The coder removed only that in-progress notice branch; notices for
`blocked`/`waiting-merge` and the done evidence notice are unchanged, and the
manifest hash was refreshed. The tester added a contract assertion that an
in-progress detail has no runner notice. Focused checks were rerun green; see
the second review record.
