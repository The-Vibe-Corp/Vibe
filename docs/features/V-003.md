# V-003 — Prozessaufrufe und Eingaben absichern

Stand: 2026-10-26
Ausgangscommit: `22322e2`
Arbeitsbranch: `feature/f8-feedback-abgeschlossen`

## Ziel

Alle externen Aufrufe von `vibe` starten Programme mit einer Argumentliste
statt über eine Shell. Namen, Pfade, Agenten und Vorlagen bleiben getrennte
Argumente und können keine Shellmetazeichen auslösen. Projektkonfigurierte
Prüfbefehle laufen nur an einer ausdrücklich benannten Shellgrenze. Reine
Leseaktionen (Projektliste, Status) führen keine Programme aus dem Projekt aus.

## Lieferumfang

- `bin/vibe` — neuer Helfer `run(argv, cwd, timeout, env)`; alle bisherigen
  `sh("...")`-Aufrufe auf Argumentlisten umgestellt; `verify_argv()` als
  einzige Shellgrenze; Prüfung von Agenten-, Emulator- und Projektnamen;
  Git-Leseaktionen ohne Projekt-Hooks.
- `bin/vibe-web.py` — `verify_bg()` nutzt `verify_argv()` statt eines eigenen
  Shellstrings.
- `bin/vibe_mcp.py` — Versionsabfrage über `vibe.run`; ungültiger Arbeitsordner
  wird gemeldet; Prozess wird nach dem Test beendet, abgewartet und die
  Standardströme werden geschlossen.
- `bin/vibe-run.sh` — prüft Agentennamen und `MAX_PACKAGES`, bevor der erste
  externe Aufruf startet.
- `tests/unit/test_process_safety.py` — 18 Tests für Leerzeichen,
  Anführungszeichen, Shellmetazeichen, ungültige Pfade, fehlende Programme,
  Timeout und Leseaktionen ohne Projektprogramme.
- `docs/import-manifest.json` — Prüfsummen und Größen der geänderten Dateien
  sowie Eintrag `V-003` unter `aenderungen`.

## Technische Umsetzung

### Einheitlicher Prozessstart

```python
run(argv, cwd=None, timeout=60, env=None) -> (returncode, output)
```

- `argv` muss eine nichtleere Liste oder ein Tupel aus Zeichenketten sein;
  sonst `ValueError`. Ein einzelner String wird nicht als Befehl akzeptiert.
- `subprocess.run` erhält die Liste ohne `shell=True`. Es gibt keine
  Zeichenkettenverkettung und keine implizite Shell.
- Ausgabe ist `stdout + stderr`, getrimmt; der Aufrufer entscheidet über die
  Darstellung.
- Fehlendes Programm: Exitcode `127` mit Meldung
  `Programm nicht gefunden: <Programm>`.
- Zeitüberschreitung: Exitcode `124` mit Meldung
  `Zeitüberschreitung nach <n> s: <Programm>`.
- Nicht ausführbares Programm (`OSError`): Exitcode `126`.
- Andere Ausnahmen werden nicht mehr pauschal zu Exitcode 1 verfälscht.

`git_run(root, *args)` startet Git lesend als
`git --no-pager -c core.fsmonitor=false …`. Damit löst `vibe list` und
`vibe status` keinen im Projekt konfigurierten `core.fsmonitor`-Hook aus.

### Strukturierte Aufrufe

| Aufruf | Umsetzung |
| --- | --- |
| tmux (Status, Start, Stopp) | `["tmux", …]` mit getrennten Argumenten |
| Agentenlauf | `tmux new-session … bash -lc <konstantes Skript> <name> <logname> <runner> <pfad> <agent>`; das Skript liest `$1`–`$4` |
| Emulator | `bash -lc 'source ~/.bashrc; exec bash "$1"' vibe-emu <skript>` |
| opencode-Server | `tmux … bash -lc 'source ~/.bashrc; exec opencode web …'` |
| Dashboard | `tmux … bash -lc 'source ~/.bashrc; exec python3 "$1"' vibe-ui <vibe-web.py>` |
| Android-Vorlage | `["android", "create", "--name=…", "--output=…", <vorlage>]` |
| Git-Initialisierung | einzelne Aufrufe für `init`, `config`, `add`, `commit` |
| Modellliste, Sitzungsliste | `["opencode", …]` |
| Doctor-Prüfsummen | `["sha256sum", "-c", <datei>, "--quiet"]` mit `cwd=VERIFY` |

Bei den `bash -lc`-Aufrufen ist das Skript eine Konstante; alle variablen
Werte werden als Positionsparameter übergeben und von der Shell nur als
Argumente eingesetzt.

### Eine ausdrückliche Shellgrenze

Projektkonfigurierte Befehle (`VERIFY_QUICK`/`VERIFY_FULL`) sind
Shellprogramme und werden bewusst an genau einer Stelle ausgewertet:

```python
verify_argv(name, mode) -> ["bash", "-lc", "source ~/.bashrc; " + verify_command(name, mode)]
```

`verify_command()` liefert weiterhin den lesbaren Anzeigetext. Für Android
wird der Aufruf mit `shlex.join` aus `bash`, Prüfskript, Projektpfad und Modus
gebildet, sodass Pfade mit Leerzeichen korrekt zitiert sind. `vibe verify`,
das Dashboard (`verify_bg`) und `vibe-run.sh` verwenden dieselbe Grenze.

### Eingabeprüfung vor dem Start

- Agentenname (CLI und `vibe-run.sh`): `^[a-z0-9][a-z0-9_-]*$` bzw.
  `^[A-Za-z0-9][A-Za-z0-9_-]*$`. Verstöße enden vor jedem tmux-Aufruf mit
  Exit 2 und der Meldung `Agentenname …`.
- Emulator-Aktion: nur `start` und `stop`; alles andere endet mit einer
  Meldung, die „Emulator“ enthält.
- Projektname (`vibe new`): unverändert `^[a-z0-9][a-z0-9_-]*$`.
- Android-Vorlage: Steuerzeichen (`NUL`, `\n`, `\r`) werden abgelehnt; der
  übrige Text bleibt ein einziges Argument.
- `MAX_PACKAGES` in `vibe-run.sh`: nur Ziffern.

### MCP-Verbindungstest

`test_local()` startet lokale Server weiterhin mit einer Argumentliste. Neu:

- Ein `cwd`, das nach Auflösung nicht existiert, wird vor dem Start mit
  `Arbeitsordner nicht gefunden: …` abgelehnt, statt still im aktuellen
  Verzeichnis zu starten.
- Nach Erfolg, Fehler oder Timeout wird der Prozess beendet, mit begrenzter
  Wartezeit abgewartet und `stdin`/`stdout`/`stderr` werden geschlossen.
- Der Timeout-Fall meldet weiterhin `Keine Antwort auf 'initialize'` mit der
  tatsächlichen Wartezeit.

## Tests

`tests/unit/test_process_safety.py` prüft:

- Argumentliste mit Leerzeichen, einfachen/doppelten Anführungszeichen,
  `$(…)`, `;`, `|`, `&&` und Umleitung; kein Marker entsteht.
- Fehlendes Programm (Exit 127) und Timeout (Exit 124, Meldung
  „Zeitüberschreitung“).
- Ungültige Argumentlisten (`[]`, Nicht-String, einzelner String) lösen
  `ValueError` aus.
- Agentenname mit Shellzeichen wird vor tmux abgelehnt; Pfad und Agent sind
  getrennte Argumente und stehen nicht im Shellskript.
- Android-Vorlage mit `;` bleibt ein Argument.
- Ungültiger Projektname legt nichts an.
- `verify_argv` liefert genau `["bash", "-lc", …]`; Android-Pfad wird für die
  Shell zitiert; fehlender Vollbefehl liefert `None`.
- Emulator-Aktion mit Shellzeichen wird abgelehnt.
- `vibe list` und `vibe status` führen weder `VERIFY_*`, das
  Emulator-Skript noch einen `core.fsmonitor`-Hook aus.
- Lokaler MCP-Server erhält Leerzeichen und `$(…)` unverändert; fehlendes
  Programm, ungültiger Arbeitsordner und Timeout werden gemeldet.
- `vibe-run.sh` lehnt einen Agentennamen mit Shellzeichen mit Exit 2 ab.

## Bekannte Grenzen

- Projektkonfigurierte `VERIFY_QUICK`/`VERIFY_FULL`-Befehle sind
  Shellprogramme. Sie werden bewusst über `bash -lc` ausgeführt. Wer
  `.vibe/project.env` schreiben darf, kann damit Programme ausführen; das ist
  die beabsichtigte Projektgrenze und keine Injektion über Namen oder Pfade.
  Die Grenze ist im Code und in der Ausgabe sichtbar, nicht versteckt.
- `vibe-run.sh` bleibt ein Bash-Skript; seine Aufrufe von `opencode` und
  `verify.sh` verwenden bereits getrennte Argumente. Der Abschlussbefehl
  `VERIFY_FULL` ist auch dort eine ausdrückliche Shellgrenze.
- Die Prüfung ersetzt keine Sandbox. Sie verhindert Befehlsinjektion über
  Namen, Pfade und Agenten, nicht böswillige Projektinhalte, die ein Agent
  später bewusst ausführt.
- `core.fsmonitor=false` gilt für die von `vibe` gestarteten Git-Leseaufrufe.
  Andere Programme, die Git im Projekt aufrufen, bleiben unberührt.
