# GH-94 — Ui css change

Ticket: GH-94 „Ui css change“ (branch `feature/m0p/gh-94`, start commit `e845c98`). This package stores the supplied style guide as a documentation reference and applies its visual language to Vibe's new UI (Nova) only. No runtime behavior, DOM hook, or classic-UI asset was changed.

## What changed

**Reference file.** The complete HTML source from the ticket is saved verbatim as [`docs/style.html`](../style.html). It is a standalone reference: theme and accent buttons in that file switch only the guide's own preview, not the application. Its stripped, CRLF-normalized SHA-256 is pinned by a test.

**Nova visual style.** [`bin/web/nova.css`](../../bin/web/nova.css) now implements “Precise Frames × Technical Density”:

- Matte token palettes for light (`#f4f3f0` canvas, `#fbfaf8` surface, `#ffffff` raised, `#eceae6` inset) and dark (`#161514`, `#1d1c1a`, `#232220`, `#141312`), with the guide's border, divider, text, and status colors and their subtle variants.
- Small radii (2/3/4/6 px), control heights (28/34/40 px), a 4/8/12/16/24/32 px spacing scale, 1 px frames, and small shadows. Existing `--nv-*` names remain the public token API; `--nv-radius-md` is an alias of the existing `--nv-radius`, and the added guide-oriented names expose the same values under names matching the reference.
- Inter / JetBrains Mono font stacks with local fallbacks only — no CDN or network font request. Buttons, inputs, badges, pills, switches, progress, tables, cards, and terminal surfaces follow the guide's dimensions; table headers are 11 px uppercase, focus is a 2 px accent outline with a 1 px offset.
- All glass/backdrop-filter, `color-mix` transparency, decorative gradients, and large shadows were removed from Nova surfaces. The `data-animations` switch still controls motion exactly as before.
- Card inner padding is now a uniform `--nv-space-4` (16 px) at every width, matching the guide's “Karten-Innenabstand 16 px” (`docs/style.html:265`). The former 32 px base with 24 px tablet and 16 px mobile overrides was replaced by this single value; no responsive layout behavior or DOM hook changed.

**Scope boundaries.** Theme/accent selectors stay on `html` because `nova-core.js` sets the attributes there; all 12 accent IDs, the default `blue`, and light/dark/auto theme selection remain functional. The guide's four example accents inform the matching Nova palettes but are not added as new settings. Classic UI files (`classic.html`, `styles.css`, `app.js`) and all JavaScript are byte-identical to the start commit. `docs/import-manifest.json` records the new `nova.css` size/hash and the change.

## Tests

The independent test agent derived coverage from the ticket and wrote the tests before production changes.

- New [`tests/unit/test_ui_style_reference.py`](../../tests/unit/test_ui_style_reference.py): exact reference file, and byte hashes pinning the three classic-UI assets to `e845c98`.
- New [`tests/browser/test_new_ui_style_screenshots.py`](../../tests/browser/test_new_ui_style_screenshots.py): renders the real `nova.css` in a local `file://` probe and samples actual Playwright screenshots plus computed styles. It checks light/dark palette pixels, a 34 px button, the 42×12 switch with a 22 px thumb, radii ≤ 6 px, opaque matte surfaces, no backdrop blur, 11 px uppercase table headers, and the 2 px/1 px focus ring.

Red phase (unmodified worktree): `tests.unit.test_ui_style_reference` → 3 tests, 2 failures (`docs/style.html` missing); `tests.browser.test_new_ui_style_screenshots` → 8 tests, 14 failures (palette bytes, 18 px button, 10/14/999 px radii, translucent card, `blur(14px)`, 15 px table header, 2 px focus offset). A scratch override with the reference values made all 8 browser cases pass, confirming the red run was not environmental.

Green phase: both new modules pass (3/3 and 8/8); focused functional suites for theme, animation, blue default, 12 accents, the 4 px spacing grid, and CSS-derived output cards pass; `tests.browser.test_shell_ui` passes 29/29. The `test_settings_ui` parity case timed out waiting for `div[data-nv-priority-strip]`; the coder reproduced the same timeout with the original `nova.css` restored from `HEAD`, so it is pre-existing and unrelated to this package.
