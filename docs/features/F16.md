# F16 — Rückfragen beantworten

Stand: 2026-11-02
Ausgangscommit: `b68fa85`
Arbeitsbranch: `feature/v-016-lebenszyklus`
Arbeitspaket: FEEDBACK.md, Eintrag F16

## Ziel

Ein Agent darf den Nutzer unterbrechen, wenn eine fachliche Entscheidung offen
ist. F16 macht diese Rückfrage im Dashboard sichtbar: mit dem Fragetext, den vom
Agenten vorgeschlagenen Auswahlmöglichkeiten und einer freien Antwort. Der
Nutzer wird benachrichtigt, wenn während einer geöffneten Seite eine Frage
gestellt wird, und kann sie direkt in der Oberfläche beantworten.

Zusätzlich gibt es einen autonomen Modus. Er kann vor oder während eines Laufs
eingeschaltet werden und gilt je Projekt. Ist er aktiv, entscheidet der Agent
ohne Antwort des Nutzers selbst und dokumentiert seine Entscheidung als Antwort
auf die Rückfrage. Schaltet der Nutzer den Modus während des Wartens ein, endet
das Warten sofort.

Die Rückfrage bleibt auch dann erhalten, wenn kein Dashboard geöffnet ist.
Beide Seiten tauschen sich über Dateien im Laufzeitordner aus; es gibt keine
Netzverbindung, keinen laufenden Server und keinen zusätzlichen Dienst.

## Ausgangslage

`bin/vibe` und das Dashboard kannten keinen Weg, wie ein Agent eine Frage an den
Nutzer stellen und eine Antwort abwarten konnte. Ein Agent konnte nur den Lauf
beenden oder eine Annahme treffen. Es gab weder einen Speicherort für offene
Fragen noch eine Oberfläche dafür.

## Fachliches Verhalten

### Frage stellen (Agent)

- `vibe ask "Frage"` legt eine Rückfrage an und wartet standardmäßig 90
  Sekunden auf eine Antwort.
- Mit `--option "A" --option "B"` schlägt der Agent Antworten vor. Die
  Reihenfolge bleibt erhalten; höchstens zehn Vorschläge sind erlaubt.
- `--no-wait` legt die Frage nur an. `--timeout <s>` ändert die Wartezeit;
  `--no-free` verbietet eine freie Antwort, wenn Vorschläge vorhanden sind.
- Wird innerhalb des Zeitlimits nicht geantwortet, endet der Befehl mit
  Exit-Code 3 und nennt den Weg zum Fortsetzen:
  `vibe ask --wait <id> --timeout <s>`.
- `vibe ask --wait <id>` wartet auf eine bereits gestellte Frage und gibt eine
  schon vorhandene Antwort sofort aus.
- Das Projekt wird aus dem aktuellen Ordner abgeleitet (längster Treffer über
  die bekannten Projektpfade). Alternativ gilt `--project <name>`; ein
  unbekannter Name wird abgelehnt, ohne etwas zu schreiben.

### Fragen anzeigen und beantworten (CLI)

- `vibe questions` listet alle offenen Rückfragen mit Projekt und nummerierten
  Auswahlmöglichkeiten (1-basiert).
- `vibe answer <id> --option <nummer>` oder `vibe answer <id> --text "..."`
  beantwortet eine Rückfrage aus dem Terminal.

### Oberfläche

- Ein Bereich „Rückfragen“ oberhalb der Projektliste zeigt jede offene Frage
  mit Projekt, Agent, Fragetext und Schaltflächen für die Vorschläge.
- Bei erlaubter freier Antwort erscheint zusätzlich ein Eingabefeld mit der
  Schaltfläche „Antwort senden“. Enter im Feld sendet ebenfalls.
- Beim ersten Sichtbarwerden einer neuen Frage erscheint ein Hinweis
  „Neue Rückfrage …“ als nicht modale Meldung; der Seitentitel zeigt zusätzlich
  `(n) vibe`. Beide Hinweise verschwinden mit der letzten offenen Frage.
- Beantwortete Fragen verschwinden sofort aus dem Bereich. Ein zweiter
  Antwortversuch wird mit einer verständlichen Meldung abgelehnt.
- Die Seite fragt den Stand alle drei Sekunden ab. Solange sich die Liste nicht
  ändert, wird der Bereich nicht neu gezeichnet; eine begonnene freie Antwort
  geht dadurch nicht verloren.
- Es werden keine Browserdialoge (`alert`, `confirm`, `prompt`) und keine
  Benachrichtigungsberechtigung verwendet.

### Autonomer Modus

- `vibe autonomous [on|off|status] [--project <p>]` schaltet den Modus um;
  ohne Aktion zeigt der Befehl den Zustand. Ohne `--project` gilt das Projekt
  des aktuellen Ordners, sonst die globale Voreinstellung.
- `vibe ask` prüft den Modus vor und während des Wartens. Ist er aktiv, wird
  die Frage zwar gespeichert und angezeigt, aber nicht auf eine Antwort
  gewartet: Der Agent erhält den Hinweis „Autonomer Modus aktiv“ und entscheidet
  selbst.
- Schaltet der Nutzer den Modus während des Wartens ein, endet das Warten
  innerhalb eines Prüfintervalls (250 ms). Der Agent entscheidet dann ebenfalls
  selbst. Der normale Zeitablauf mit Exit-Code 3 gilt nur bei ausgeschaltetem
  Modus.
- Seine Entscheidung dokumentiert der Agent mit
  `vibe answer <id> --text "..." --by agent`. Damit verschwindet die Rückfrage
  und die Entscheidung ist nachvollziehbar gespeichert.
- Der Modus gilt je Projekt. Die Oberfläche bietet ihn im Projektdetail und
  direkt an jeder Rückfrage („Autonom entscheiden“) an; beide Wege funktionieren
  auch während eines laufenden Agenten.

## Technische Umsetzung

### Speicher (`bin/vibe_questions.py`)

- Je Rückfrage zwei Dateien in `$VIBE_RUNTIME/questions`:
  - `<id>.json` — unveränderliche Frage mit `id`, `project`, `agent`, `text`,
    `options`, `free_text`, `created`.
  - `<id>.answer.json` — Antwort mit `option`, `option_text`, `text`, `at`,
    `by`.
- Die ID hat die Form `q` + 12 Hexzeichen und wird mit
  `^q[0-9a-f]{12}$` geprüft, bevor irgendein Pfad entsteht. Manipulierte IDs
  (`../`, Pfadtrenner, fremde Zeichen) werden abgelehnt.
- Beide Dateien werden über `vibe_storage.write_text(..., expected=MISSING)`
  angelegt. Eine vorhandene Antwort kann deshalb nicht überschrieben werden;
  auch zwei gleichzeitige Antworten ergeben genau einen Gewinner.
- Grenzen: Fragetext und Antwort je 4000 Zeichen, Vorschlag 200 Zeichen,
  höchstens 10 Vorschläge, Projekt/Agent/Quelle 120 Zeichen. Leere, doppelte
  oder Steuerzeichen enthaltende Vorschläge werden abgelehnt. Ungültige
  Eingaben erzeugen keine Datei.
- `open_questions()` liefert unbeantwortete Fragen nach `created` und `id`
  sortiert. Eine defekte Datei wird übersprungen, damit die übrigen Fragen
  sichtbar bleiben; gelesene Felder werden dabei auf Typ und Grenzen geprüft,
  damit eine manipulierte Datei keine Riesentexte oder falschen Typen in die
  Oberfläche bringt.
- `wait()` prüft den Antwortstand in kurzen Abständen und liefert bei
  Zeitablauf `None`.
- `project_for_path()` vergleicht echte Pfade und nur ganze Pfadpräfixe
  (`/w/proj2` gehört nicht zu `/w/proj`).
- `wait_for()` prüft zusätzlich einen `stop`-Rückruf und liefert
  `("answer", Antwort)`, `("timeout", None)` oder `("stop", None)`. `wait()`
  bleibt als einfache Variante erhalten.

### Autonomer Modus (`bin/vibe_autonomous.py`)

- Zustand in `$VIBE_RUNTIME/autonomous.json`:
  `{"version": 1, "projects": {"<projekt>": {"enabled": true, "changed": "..."}}}`.
  Ein leerer Projektname ist die globale Voreinstellung für Fragen ohne Projekt.
- Die Datei liegt bewusst **außerhalb** von `questions`. Die Sandbox bindet nur
  `questions` beschreibbar ein; ein Agent kann den Modus deshalb nicht selbst
  einschalten und auch keine fremde Freigabe vortäuschen.
- Fehlt die Datei oder ist sie unlesbar, gilt der Modus als aus. Ein Lesefehler
  darf nie dazu führen, dass ein Agent ohne ausdrückliche Freigabe allein
  entscheidet.
- Geschrieben wird über `vibe_storage.write_text` mit Prüfsummenkontrolle und
  erneutem Versuch bei gleichzeitiger Änderung. Projektnamen werden auf Text,
  Steuerzeichen und 120 Zeichen geprüft.

### CLI (`bin/vibe`)

- Neue Befehle `ask`, `questions`, `answer` und `autonomous`; Aufrufhilfe und
  Befehlstabelle wurden ergänzt.
- Zahlen werden geprüft (Zeitlimit nicht negativ, `--option` eine Zahl ab 1).
  Die CLI rechnet 1-basiert, das Modul 0-basiert.
- `answer --by <quelle>` dokumentiert, wer geantwortet hat (`cli`, `web` oder
  `agent`); ohne Angabe gilt `cli`.
- Fehler werden als verständliche Meldung mit Exit-Code ungleich 0 ausgegeben;
  ein Zeitlimit endet mit Code 3, der autonome Modus mit Code 0 und dem
  Entscheidungshinweis.

### HTTP-API (`bin/vibe-web.py`)

- `GET /api/questions` liefert `{"questions": [...]}` mit allen offenen Fragen.
- `POST /api/questions` mit `{"action": "answer", "id": ..., "option": n}`
  oder `{"action": "answer", "id": ..., "text": "..."}` speichert die Antwort
  und liefert `{"ok", "message", "questions"}` mit dem neuen offenen Stand.
- Beide Wege sind tokenpflichtig. Ungültige IDs, falsche Typen, ein zweiter
  Antwortversuch und unbekannte Aktionen ergeben HTTP 400 mit `ok: false`; die
  Frage bleibt offen.
- Die Quelle wird als `by: "web"` gespeichert.
- `GET /api/autonomous?name=<projekt>` liefert `project`, `enabled` und
  `changed`; `POST /api/autonomous` mit `{"name", "action": "on"|"off"}`
  schaltet den Modus. Unbekannte Projekte ergeben 404, unbekannte Aktionen 400;
  beide Wege sind tokenpflichtig.

### Oberfläche (`PAGE`)

- Neuer globaler Bereich `#questions` zwischen Kopfzeile und `main`, mit
  `role="region"`, `aria-label="Rückfragen"` und `aria-live="polite"`.
- Karten tragen `data-question="<id>"`; Vorschläge `data-option="<index>"`;
  das freie Feld hat `aria-label="Eigene Antwort zu <id>"`.
- `pollQuestions()` fragt alle drei Sekunden ab; `showQuestions()` vergleicht
  eine Signatur aus IDs, Texten und Vorschlägen und zeichnet nur bei
  Änderungen neu. `answerQuestion()` prüft `ok` und übernimmt die
  zurückgelieferte offene Liste.
- Jede Karte mit Projekt bietet „Autonom entscheiden“: Der Klick schaltet den
  Modus für dieses Projekt ein und meldet „Autonomer Modus … aktiviert“.
- Das Projektdetail enthält eine Karte „Autonomer Modus“ mit Zustand und
  Umschalter. Beide Wege wirken sofort, auch während ein Agent auf eine Antwort
  wartet.

### Sandbox (`bin/vibe_sandbox.py`)

- `bwrap_argv(..., runtime=...)` bindet ausschließlich `<runtime>/questions`
  beschreibbar ein und legt den Ordner an. Der übrige Laufzeitordner mit
  Token, Protokollen und Laufregister bleibt unerreichbar.
- Die Bindung erfolgt vor dem Schreibschutz von `/tmp`: bubblewrap legt den
  Einhängepunkt im privaten tmpfs an und schützt danach den übrigen Inhalt von
  `/tmp`. Dadurch funktioniert auch ein Laufzeitordner unter `/tmp`, während der
  restliche temporäre Bereich schreibgeschützt bleibt.
- `runtime` kommt aus `VIBE_RUNTIME` oder `$VIBE/_logs` — dieselbe Ableitung
  wie im Paketläufer. Ohne Laufzeitordner entsteht keine Bindung.
- Kann der Rückfrageordner nicht angelegt werden, läuft der Agent ohne
  Rückfragekanal weiter und der Grund wird auf stderr gemeldet; der Lauf
  scheitert nicht an einer nicht schreibbaren Laufzeit.

### Paketläufer (`bin/vibe-run.sh`)

- Der Laufhinweis nennt `vibe ask "Frage" --option ...`, den Exit-Code 3 bei
  Zeitablauf und das Fortsetzen mit `vibe ask --wait <id>`.

## Grenzen

- Die Rückfrage ist ein Dateiaustausch, kein Live-Kanal. Ohne geöffnetes
  Dashboard oder Terminal bleibt sie offen, bis jemand antwortet; der Agent
  wartet nur bis zum Zeitlimit.
- Der autonome Modus ersetzt keine fachliche Prüfung. Er verschiebt die
  Entscheidung auf den Agenten; dessen Entscheidung ist als Antwort mit
  `by: "agent"` sichtbar, aber nicht nachträglich vom Nutzer bestätigt.
- Der Modus gilt je Projekt und nicht je Lauf. Ein späterer Lauf desselben
  Projekts bleibt autonom, bis der Nutzer ihn ausschaltet; der Zustand ist im
  Projektdetail und mit `vibe autonomous status` sichtbar.
- Lesen ist in der Sandbox nicht eingeschränkt. Der Schutz betrifft das
  Schreiben: Ein Agent kann den Laufzeitordner lesen, aber nur `questions`
  beschreiben. Das entspricht der bestehenden Sandbox-Grenze.
- Es gibt keine Push-Benachrichtigung außerhalb der geöffneten Seite; bewusst
  ohne Berechtigungsdialog des Browsers. Der Hinweis ist die Meldung im
  Dashboard und der Zähler im Seitentitel.
- Eine Rückfrage wird nicht nachträglich geändert. Ist sie einmal gestellt,
  bleibt der Wortlaut unverändert; eine Korrektur wäre eine neue Frage.
- Die Auswahl wird als Index gespeichert. Nach dem Anlegen ist die
  Reihenfolge unveränderlich, daher bleibt der Index eindeutig.
