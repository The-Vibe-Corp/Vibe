# GH-99 — UI Session Rework

Delivery record for work package GH-99. Ticket: GH-99 "UI Session Rework"
(branch `feature/m0p/gh-99`, start commit `bd5fc37`).

## Scope and decisions

The work package makes the work package the durable owner of sessions and
costs. Sessions are no longer identified by display name, and the cost
overview no longer depends on live harness data. The former "Run behaviour"
setting is removed entirely.

**Spec conflict (flagged and decided in autonomous mode).** `SPEC.md` lines
153–155 previously required an explicit global `vibe limits stop|continue`
setting in `<state>/limits.json`. GH-99 §4 requires that setting and its
function to be removed completely. Autonomous mode made a user question
impossible; the explicit, more recent ticket requirement was followed and
`SPEC.md` was updated accordingly: quota and login failures always stop a run
immediately, and a legacy `limits.json` is ignored. The historical record
[V-027](V-027.md) is marked as superseded.

## What changed

- **Package-owned sessions:** validated harness session IDs are stored in
  `sessions` on the package record in `.vibe/tickets.json`. The same session
  cannot be attached to another package or project. `vibe sessions
  attach|for-package|finish-package|migrate` operate on that stored
  assignment. A run resumes the package's stored session when one exists;
  a fresh session is created only when no stored session can be continued or
  an explicit restart was requested.
- **Display and cleanup:** the project overview groups sessions under their
  work package. The technical ID is muted, truncated, and carries a tooltip
  with the full ID. Only successful work-package completion flushes usage and
  then clears the package's sessions and registry entries; pause, abort and
  failure never trigger cleanup.
- **Package costs:** per-session usage is persisted in `costs` on the package
  record and summed across all of its sessions. Re-processing overwrites a
  session's entry instead of adding it again. `vibe costs` and `/api/costs`
  read those persisted records; they work after cleanup and without the
  opencode database. `vibe sessions migrate` adopts only unambiguous legacy
  assignments and reports the session IDs it could not map rather than
  guessing.
- **Run behaviour removed:** the Nova settings section/toggle, the
  `/api/limits` routes, the `vibe limits` command, the `vibe_limits.py` module,
  its install/manifest entries and the runner's `LIMIT_MODE` branch are gone.
  Existing `limits.json` files are ignored and cannot change run behaviour.
- **Post-review hardening:** the optional module imports in `vibe_runs.py` are
  guarded, and `vibe sessions attach` validates the new ID (including global
  single ownership) before replacing the stored assignment. A rejected attach
  therefore cannot destroy the previous assignment; the corresponding test
  asserts this guarantee.
