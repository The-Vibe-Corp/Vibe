# V-022 — Ordnung im Git als allgemeine Projektregel

Stand: 2026-11-02
Ausgangscommit: `055cd71`
Arbeitsbranch: `feature/v-022-general-git-rules`

## Ziel

Die allgemeinen vibe-Regeln sollen neben dem Aufräumen des Projektordners
auch die Ordnung im Git verbindlich beschreiben. Das gilt für bestehende und
neue Projekte:

- Änderungen laufen auf einem Feature-Branch, nicht direkt auf `main`,
  `master` oder einem geschützten Branch.
- Jedes abgeschlossene Arbeitspaket wird als zusammenhängender Commit
  gesichert; fremde oder temporäre Änderungen werden nicht mitcommittet.
- Vor dem Commit werden `git status` und der relevante Diff geprüft; gestagt
  werden ausschließlich Dateien des eigenen Arbeitspakets.
- Protokolle, Build-Artefakte, Arbeitskopien und Screenshots ohne Nachweiswert
  bleiben aus dem Repository.
- Vorbestehende Änderungen werden nicht gelöscht, überschrieben, gestasht
  oder mitcommittet.
- Historie wird nicht umgeschrieben; Force-Push und Push erfolgen nur mit
  ausdrücklicher Freigabe.

## Fachliche Umsetzung

Der verwaltete Block `<!-- vibe:general-rules -->` enthält jetzt zwei
Abschnitte:

1. `## Projektordner sauber halten`
2. `## Ordnung im Git halten`

Der Block steht in allen sechs mitgelieferten Projektvorlagen
(`templates/*/AGENTS.md`), in der `AGENTS.md` dieses Repositorys und in
`GENERAL_RULES` von `bin/vibe`.

`vibe init` ergänzt den Block weiterhin genau einmal, wenn er fehlt. Zusätzlich
aktualisiert es einen bereits vorhandenen, vollständig abgeschlossenen Block
auf den aktuellen Stand. Dabei bleiben alle Inhalte außerhalb der beiden
Marker unverändert. Ein unpaariger Marker (Start ohne Ende) wird nicht
angetastet, damit keine fremden Inhalte überschrieben werden. Symlinks werden
weiterhin nicht verfolgt.

Damit erhalten auch Projekte, die bereits mit der älteren V-021-Regel
vorbereitet wurden, die Git-Regeln beim nächsten `vibe init`, ohne dass ihre
eigene `AGENTS.md` neu aufgebaut wird. Ist eine `AGENTS.md` nicht gültig
UTF-8, bleibt sie unverändert, statt ungültige Bytes durch Ersatzzeichen zu
ersetzen.

## Grenzen

Ein GitHub-Aufräumen war nicht möglich: Das Repository hat keinen
konfigurierten Remote (`git remote -v` ist leer), und die GitHub-CLI `gh` ist
in der Umgebung nicht installiert. Ohne Repository-URL und Zugang wurden keine
Remote-Branches gelöscht. Lokale Feature-Branches wurden ebenfalls nicht
entfernt, weil ihre Löschung nicht Teil des bestätigten Umfangs war.
