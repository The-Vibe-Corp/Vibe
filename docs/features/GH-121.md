# GH-121 — Incorrect closed tickets number shown

Delivery record for bug ticket GH-121 (GitHub issue #121). Work was done on
`feature/m0p/gh-121` from start commit `2812725`; no production installation
was modified.

## Symptom

In the Nova UI's project **Work** tab, the `Show done` button reported a number
that was too small, for example `(3)` when more tickets were closed. The count
never included closed bugs or feedback items.

## Root cause

The backend deliberately splits the ticket store into two API arrays:
`data.tickets` holds packages (`task`, `feature`) and `data.feedback` holds bugs
and feedback. `bin/web/nova-project.js` combined both into `allItems` for the
work board, but built the `Show done` label from `nvpCount(tickets, 'erledigt')`
at two places: the initial button label and the count passed to
`nvpWireWorkFilters`, which rewrites the label when the toggle is used. The
number therefore reflected only closed packages.

## What changed

- `bin/web/nova-project.js` gained `nvpDoneCount(list)`, which counts rows with
  the existing `nvpIsDone()` predicate (`erledigt` or `done`). One combined
  count is computed from `allItems` and used for both the initial label and the
  filter wiring, so the number stays correct after toggling.
- The done-grid visibility, `aria-pressed`, hooks, search, and quick-filter
  behavior are unchanged. The overview tile `Erledigt` still counts only closed
  packages with proof, as its label and existing coverage require.
- `docs/import-manifest.json` carries the refreshed size and SHA-256 of the
  changed frontend file and a GH-121 change entry.

## Scope decision

Autonomous mode was active. The ticket asks for the number of closed tickets to
be correct and explicitly names the missing bug/feedback types; therefore the
toggle count covers every closed ticket type, while the separate overview tile
remains a package metric. No state, API, or ticket-store schema change was
needed.
