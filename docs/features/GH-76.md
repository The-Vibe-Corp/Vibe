# GH-76 — Hide the mandatory (template) AGENTS.md section

Delivery record for work package GH-76.

## What changed

- **Hidden platform instructions.** The English platform text from the ticket is
  now a single constant in `bin/vibe_harness.py` (`PLATFORM_INSTRUCTIONS`) and is
  written as `platform_instructions.md` into the run's state directory, outside
  every project and outside the personal opencode configuration. The new
  `vibe platform-instructions --directory DIR` subcommand (and the identical
  `vibe_harness.py platform-instructions` entry) writes the file atomically,
  refreshes it idempotently, refuses symlinked destinations and prints the
  absolute path.
- **Delivery to opencode.** For every opencode-harness run, `bin/vibe-run.sh`
  merges `"instructions": ["<absolute path>"]` into
  `OPENCODE_CONFIG_CONTENT` before the existing project-model merge. Existing
  configuration keys are preserved; runs without project models still receive
  the entry. Because the inline configuration is now always present, the runner
  uses `--standalone` / its private server instead of reusing a pre-running
  shared server that would not know the instructions. The Pi path is unchanged.
- **No built-in rules block in project files.** `GENERAL_RULES` and
  `ensure_general_rules` and their call sites (`vibe run`, `vibe init`,
  `vibe new`, GitHub adoption) were removed. `vibe init/new/clone` no longer add
  or update any block in a project `AGENTS.md`; existing files stay untouched.
  The legacy marker constants and the view/split helpers remain so old blocks
  stay readable.
- **Clean templates.** All five `templates/*/AGENTS.md` lost the managed marker
  block and keep only their type-specific instructions.
- **AGENTS.md editor.** `agents_file_save` now preserves an existing legacy
  block byte-identically and writes `before + after` for block-less files
  (the former "no managed block" rejection is gone). Unpaired markers, markers
  in the free parts, digest protection and symlink protection are unchanged.
  In the dashboard, the upper textarea is no longer disabled for block-less
  files, so both parts are editable; the card wording now describes the
  preserved/protected legacy block instead of a per-run refresh.
- **Repository reference.** Root `AGENTS.md` is ignored runtime state
  (`.gitignore`), not a tracked repository file. The worktree's synced copy was
  corrected for this run because the test reads it there; the correction is not
  part of the commit. The project's own `AGENTS.md` copy in the integration
  checkout (which agents must not touch) still has the broken
  `docs/verification-baselines.md` reference; the user should apply the same
  one-character correction there so future synced working notes carry the right
  reference. The repository's German legacy block was intentionally left
  untouched.

## Interface decision

The runner writes the platform file through `$BIN/vibe_harness.py
platform-instructions`, not through `$BIN/vibe`. Many runner tests replace
`$INSTALL/bin/vibe` with a fake to exercise FRITZ/error paths; calling the CLI
would break those fixtures and hide real runner behavior. Both entry points use
the same implementation in `vibe_harness.py`; the public `vibe
platform-instructions` subcommand in `bin/vibe` delegates to it.

## Known pre-existing observation

The runner aborts a Pi run when a real `vibe_keys.py` is installed: the AP23
key sync reports the harness as unsupported. That behavior predates GH-76 but
was previously hidden by a less faithful test installation; the more faithful
runner fixture now exposes it. The fix belongs to the key-sync wiring and is a
follow-up outside this package.
