# GH-96 — Bugs from GH-89

Delivery record for work package GH-96. Ticket: GH-96 „Bugs from GH-89" (branch
`feature/korbat/gh-96`, start commit `f2dd725`).

## What changed

**AK9 regression restored.** Since GH-76 the runner set `HAS_INLINE_CONFIG=1`
for every opencode run, but the shared-server branch required
`HAS_INLINE_CONFIG != 1`. A reachable shared server was therefore never
addressed, and `test_private_server.SharedServerKeptTest.test_reachable_shared_server_keeps_the_shared_target`
failed deterministically. The runner now restores the B13/AK9 contract: an
opencode run outside the sandbox reuses a reachable shared server exactly when
no effective project configuration exists and the password file is non-empty.
Without a password the run stays `--standalone`, because it could not
authenticate; with effective project configuration the private-server path is
used as before (B1). The sandbox and Pi paths are unchanged.

**Effective project configuration flag.** The merge script in
`bin/vibe-run.sh` now receives a flag file (`<run log>.projektmodelle`) and
writes `1` into it when `clean`, `opencode_models` or `opencode_disabled` is
non-empty — so project models and `opencode` entries, including merely disabled
ones, count. The runner reads the flag after the merge and uses
`HAS_PROJECT_MODELS` for the server choice. Write errors fail closed through the
existing `fail()` path without leaking configuration contents.
`HAS_INLINE_CONFIG` is removed; the platform instructions are still merged into
`OPENCODE_CONFIG_CONTENT` for every opencode run (GH-76 unchanged).

Branch:

```bash
elif [ "$HAS_PROJECT_MODELS" != 1 ] && [ "$HAS_SERVER_PASSWORD" = 1 ] && server_is_up; then
```

**Living documentation.** `docs/features/B13.md` (active conditions and the AK9
row) and `docs/features/B1.md` (server choice) now state the password and
project-configuration conditions. `docs/features/F7.md` was checked: its
statements describe the sandbox `--standalone` requirement and the
per-instance state roots, not the general shared-server reuse, so it was left
unchanged. `docs/import-manifest.json` records the new size/hash of
`bin/vibe-run.sh`, the change, and the new `stand` date.

## Feedback on the GH-89 documentation

The ticket asked whether the GH-89 functionality was missing from the living
documentation or whether misleading instructions remain.

- **The functionality is covered.** `docs/features/F6.md` documents `--yes`,
  `--set-default`, and the protection of a personal configuration whose
  `profiles.prod` points elsewhere. `docs/features/F7.md` documents the
  per-instance `/dev/shm` roots (`vibe-opencode-<uid>`, `vibe-sandbox-<uid>`,
  `vsb-<uid>`) and the source ≠ destination binding; its CLI-evidence note
  names GH-89 explicitly. `docs/features/B4.md` documents the
  per-instance state directory used for the Pi agent files. The objection that
  the functionality was "not mentioned" is therefore unfounded.
- **Remaining gap.** `docs/features/GH-89.md` itself is written in German,
  while current instructions require English for delivery records. That is a
  documentation-language gap in the GH-89 package; it is not corrected here.
