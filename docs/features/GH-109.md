# GH-109 — Agents UI adjustments

Delivery record for work package GH-109, ticket "Agents UI ANpassungen"
(`TICKET-GH-109.json`). Package branch `feature/m0p/gh-109`, start commit
`8997d4d1d5beb1ebcc8806cf23d3ebc2c4ba0e02`.

The change is confined to the Nova agents list and editor
(`bin/web/nova-agents.js`, `bin/web/nova.css`, `bin/web/i18n.js`). The classic
interface, storage and the agent API are untouched. The restore action now
sends the already-supported `backup` field; no backend contract change was
needed.

## What changed

- **Header alignment.** The agents toolbar carries `nv-agents-toolbar`. The
  page title and the "New Agent" button no longer contribute stray margins,
  and both the enhanced `.nv-filter-bar` search wrapper and the inner search
  container are content-sized with zero margin. Title, search field and button
  share one vertical centerline with consistent 12 px gaps; wrapping on narrow
  screens is preserved.
- **Agent cards.** `.nv-agent` is a flex column and the Edit/Delete row has
  `nv-agent-actions` with `margin-top: auto`. Grid cards stretch to equal row
  height, so both buttons sit at the same bottom offset on every card
  regardless of description length or extra badges. The hidden delete
  confirmation remains inside the card.
- **Restore version selection.** The restore confirmation contains
  `select[data-nv-restore-version]` with an accessible label, "Newest first"
  hint and the retained `span[data-nv-backup-info]`. All backups from
  `GET /api/agent` are listed newest-first with the newest preselected; the
  list is refreshed when the confirmation opens, so newly created backups are
  selectable. The confirm button sends the chosen filename as `backup` to
  `POST /api/agent`. With no backups, the selector and confirm button are
  disabled and an explicit "No backup available" message is shown. The
  confirmation text no longer claims that only the newest backup is used;
  success toast, error handling and `NV.render()` are unchanged.
- **Project assignments.** `renderAssignments()` emits exactly one
  `div[data-nv-assign-row="<project>"]` per project, containing the visible
  project name, a `<label>` with the checkbox and the visible text
  "Assign"/"Zugewiesen", and the existing model-override combobox. The
  checkbox keeps `data-nv-assign`, its project-specific `aria-label` now
  includes the explicit assign label. The save loop still reads the same
  checkbox and combobox hooks.
- **Translations and manifest.** New German source strings have English
  translations in `bin/web/i18n.js`. `docs/import-manifest.json` has a GH-109
  change entry with refreshed size and SHA-256 for the three changed web files.
