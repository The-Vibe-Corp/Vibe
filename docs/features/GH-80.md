# GH-80 — Check integration branch test fails for regression

Ticket: GH-80, "Check integration branch test fails for regression" (bug).

## What changed

Investigation of the unit and browser test failures reported for the
integration branch full verify (dev) and the nightly full run. The reported
failures split into three groups; only the first is fixed here.

1. Real follow-up gaps after intentional source changes (fixed):
   - `bin/vibe_harness.py` was changed in PR #79 without updating
     `docs/import-manifest.json`, breaking the quick gate,
     `tests.unit.test_import_manifest`, and
     `tests.unit.test_verify_script.test_repository_quick_check_passes`.
     The manifest now carries the shipped file's real size and checksum, a
     change-log entry, and the updated `stand` date.
   - PR #79 renamed `docs/verification_baselines.md` to
     `docs/verification-baselines.md`. `tests.unit.test_ap7_korbat_rules`
     and `tests.unit.test_gh76_platform_instructions` still enforced the
     underscore name (AssertionError in the integration run; FileNotFoundError
     in the nightly run because the tests opened the old path). Both now
     enforce the hyphen name.
   - PR #75 translated and consolidated `SPEC.md`; the canonical section
     `## Git & work-package closing (runner-owned)` no longer exists as a
     heading and `GITHUB_AUTO_MERGE` / conflict-repair commands moved to the
     English platform instructions in `bin/vibe_harness.py`.
     `tests.unit.test_ap4_korbat_rules` now verifies the same acceptance
     intent (T-I1: one canonical source for runner-owned closing, PR-only
     default, opt-in auto-merge, documented conflict repair) against the
     current SPEC.md and platform instructions.
   - `tests.browser.test_ap8_checkout_ui`: GH-76 removed the managed German
     rules block from templates, so the checked-out project's AGENTS.md now
     comes from the template (`# AGENTS fuer …`); and the "without token"
     clone case must send no credentials, because the session cookie
     established by the page is valid authentication per SPEC. Verified at
     the starting point that the without-token case failed identically
     before these merges, i.e. it is pre-existing drift, not a new code
     regression.

2. No code regression found (environment/timing, not fixed here):
   - `tests.browser.test_ap9_github_ui`, `tests.browser.test_gh56_work_ui`,
     `tests.browser.test_gh67_work_ui`: Playwright timeouts in the loaded
     nightly run; all three pass deterministically in the sandbox worktree.
   - `tests.unit.test_setup_vibe` and `tests.unit.test_b6_pi_runner_events`
     failed in the integration run with an unparsable ("unknown") error and
     are stable green locally across repeated runs; not reproducible here.

3. Baseline/environment mismatch: the nightly run reported the documented
   pre-existing `test_ap4_korbat_rules` signature (`sha256:7ea99e…`) as a
   new regression. The integration tree (no sandbox) and the feature
   worktree (sandbox) share one `VERIFY_ENV` label, so a baseline recorded
   for one location is missing in the other. Strategy: see
   `docs/verification-baselines.md`, section "Environments and locations".
