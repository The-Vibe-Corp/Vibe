# GH-104 — Retire finished subagents from the active output list

Ticket: GH-104 „project - output UI: orphaned subagents“ (branch
`feature/m0p/gh-104`, start commit `ffa0058`). The package fixes stale
subagent cards at the lifecycle root: a finished child leaves the active list
at its own terminal event, a new ticket in the same run does not inherit
leftovers, and the retired output stays available.

## What changed

**State model (`bin/vibe_runs.py`).** `<log>.state.json` keeps `subagents` as
the active list only and adds a bounded `history` list (50 entries, oldest
out). `load_subagent_state` preserves both lists; `save_subagent_state` trims
both.

**Immediate retirement.** A terminal status (`completed`, `error`, `failed`,
`cancelled`, `canceled`) moves the entry from `subagents` to `history` while
its output, agent, description, prompt, and timestamps are kept. This covers
opencode `tool_use` task events (including B12 background metadata status),
Pi `tool_execution_end` (`completed`/`error`), and the cancelled statuses.
Concurrent children remain active.

**Per-attempt reset.** At the start of every `stream_events(..., attempt=True)`
call, leftover active entries are retired before the event stream is read, so
a still-`running` child of the previous ticket cannot carry over. Entries
created within the current stream are untouched, and the reset state is saved
once.

**Revival.** Later events of the same retired child session restore its
`history` entry to the active list (`status=running`, `ended=0`) with the
accumulated output intact. Sibling entries stay retired.

**API projection (`bin/vibe-web.py`).** `/api/subagents` exposes only active
entries; terminal statuses are filtered defensively and a child the opencode
server reports as known-but-inactive is dropped from the active projection
without writing state from the web process. `/api/subagent-output` falls back
to `history`, and `/api/steer` still resolves captured subagent sessions, so
stored output and target resolution stay available. Emitted log lines are
never removed.
