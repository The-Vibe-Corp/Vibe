# GH-124 — Improvements Model list in settings

Delivery record for feature ticket GH-124 (GitHub issue #124). Work was done on
`feature/m0p/gh-124` from start commit `2812725` in the isolated package
worktree. No production installation was modified; no real model calls or
functional MCP calls were made.

## What changed

- **Nova model list.** The table `table[data-nv-models-table]` now lives inside
  `details[data-nv-models]` instead of below it. The section head keeps the
  refresh button and the stand line. Collapsed, no model row is visible;
  expanded, all models are shown inside the expandable area.
- **Refresh with real, persisted detail lookup.** `POST /api/agents
  {action:'refresh_models'}` still fetches all models from the active harness,
  then looks each ID up in the local catalogue (`data/models.json`, runtime
  `<install>/models.json`) and writes the enriched `info` map plus
  `info_unvollstaendig` into `<state>/models-cache.json` atomically. GET and the
  refresh reply reuse the persisted view; a failed refresh leaves the cache
  untouched. Missing, incomplete and stale catalogue values carry an explicit
  `hinweis` instead of an unexplained "unknown", and no facts are invented.
  The success feedback names how many models have incomplete data; failure and
  empty cases remain explicit. The Nova toast is composed from the structured
  reply so it is localized in German and English.
- **Separate payload for the classic UI.** To keep the protected classic
  dashboard byte-identical, `/api/agents` still serves the raw catalogue under
  `info`; the enriched details are exposed as `model_details` for Nova only.
  `bin/web/app.js` is unchanged.
- **Nova "Model Catalogue" removed.** `details[data-nv-model-catalog]`, its
  `models-prices` action and its translation keys are gone. The editable price
  view remains reachable through the evaluations/costs area; the classic
  dashboard's catalogue is unaffected.
- **Configured models.** `configured_models` is the union of agent-file models,
  role defaults, the vibe agent model and profile assignments. Nova marks
  matching rows (`data-nv-configured` plus a CSS highlight) and offers a
  `input[data-nv-models-filter='configured']` toggle. The choice is persisted
  in `localStorage` (`nv-models-configured-filter`) and therefore survives
  reload, refresh and configuration changes.
- **Documentation.** [Agents, models and profiles](current/agents-models.md) is
  the living feature doc. The older contracts in [F34](F34.md) and
  [GH-57](GH-57.md) now point at this ticket where they were superseded.

## Verification

Environment: isolated package worktree, temporary HOME/VIBE/state/runtime
directories, dedicated loopback ports, fake harness, no production instance.

- Test-first red phase: 11 unit cases (`ModelsRefreshTest`, `ModelsCatalogTest`)
  and 10 browser cases (`ModelsLayoutTest`, `ModelsSectionTest`,
  `ModelsCatalogSectionTest`) failed for the intended reasons — missing
  `configured_models`/`model_details`/cache `info`, old refresh message, table
  outside the `<details>`, catalogue still present, no highlight/filter, and
  bare "unknown" details. The later filter-persistence case also failed
  before its fix (`checkbox is_checked()` false after reload).
- Green phase: `python3 -m unittest tests.unit.test_settings` → 39/39 OK;
  Playwright suite `tests.browser.test_settings_ui.ModelsLayoutTest`,

  `python3 -m unittest tests.unit.test_ui_style_reference` → 3/3 OK (classic
  assets byte-identical); `python3 -m unittest tests.unit.test_model_catalog
  tests.unit.test_agent_management tests.unit.test_web_routes` → 271/271 OK.
- Classic browser suite `tests.browser.test_models_ui` → 5/6 OK. The single
  failure (`test_detail_separates_facts_and_assessments_with_sources` expects
  German `[fakt]` while the ambient UI is English) was reproduced on a clean
  `git archive` of the start commit; it is pre-existing and unrelated.
- `bash scripts/verify.sh quick` → Exit 0; `bash scripts/verify.sh package` →
  Exit 0.
- Authorized baseline bootstrap: `bash scripts/verify.sh full
  --write-baseline` → Exit 7 with a new `head_of_vibe` section in the local,
  gitignored proposal (2796 tests, 15 known-red modules). The section was

  `BASELINE-OK`**: 2796 tests, 64/79 modules passed, 15 known-red modules,
  `env=head_of_vibe`.
