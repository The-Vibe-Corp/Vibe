# GH-117 — setting storage

Delivery record for work package GH-117, ticket "setting storage"
(`TICKET-GH-117.json`). Package branch `feature/m0p/gh-117`, start commit
`74e001e3d5f7d79f6e5b40e0caa2b33238b1f5e9` (GH-115).

## What changed

- **Versioned local settings file.** New `bin/vibe_settings.py` stores the five
  personal preferences in `<state>/settings.json` as
  `{"version": 1, "settings": {...}}`: theme (`light`, `dark`, `auto`), accent
  (12 choices, `blue` default), enabled/disabled features (ten known IDs),
  favorite projects and favorite agents. Reads never raise; writes use
  `vibe_storage.write_text` for atomic replacement.
- **Per-key fallback and preservation.** Every value is validated on its own.
  Missing, invalid or unknown values fall back to safe defaults (`light`,
  `blue`, no enabled features, empty favorites) without changing the other
  keys. Unknown keys and a schema version newer than 1 are kept verbatim in
  the file and never downgraded; they are ignored in the effective view until
  the running version understands them. Patches are merged, not replaced, so
  a save of one preference cannot clear another.
- **Authenticated API and HTML bootstrap.** `bin/vibe-web.py` serves GET/POST
  `/api/settings`; both shells embed the effective view as an HTML-escaped
  `vibe-settings` meta tag. The UI therefore restores preferences on a restart
  or after an application update without an extra request or an unauthenticated
  endpoint.
- **Frontend write-through and migration.** `nova-core.js` exposes
  `NV.settings`, `NV.settingsStored` and `NV.saveSettings(patch)`; theme,
  accent, feature toggles and the project/agent pin buttons persist partial
  changes and keep the legacy `nv-*` localStorage keys as mirrors. On first
  load with no server file, existing localStorage values are migrated in one
  POST; once a file exists, the server is authoritative.
- **Documentation and manifest.** The living
  [UI shell documentation](current/ui-shell.md) describes the storage,
  fallback and migration contract; `docs/import-manifest.json` carries the
  GH-117 entry with refreshed sizes and SHA-256 values. A German scope page is
  kept in Trillium as note `vDrJ39qv9XF1` (see
  [trilium-index.md](../trilium-index.md)).

## Autonomous decisions

Autonomous mode was active, so the coordinator decided: (1) browser
`localStorage` stays as a compatibility mirror and migration source, while the
server file is authoritative once present — direct user changes in the UI are
never lost, and old browser profiles are carried over; (2) validation is
per setting instead of all-or-nothing, because one newer or corrupt key must
not cost the user their other preferences; (3) unknown future keys and higher
versions are preserved on write instead of being discarded; (4) favorites are
filtered entry-by-entry (with deduplication and a limit of 200) rather than
rejecting a whole list because of one bad entry; (5) the classic shell stays
byte-identical to its baseline (it does not load `nova-core.js`), so meta
injection and migration apply only to the Nova dashboard. The two new API
routes were added to `docs/baseline.md` to keep the API inventory complete.

## Post-review correction

Review round 1 (`docs/reviews/GH-117-review-1.md`) returned
`CHANGES REQUIRED` for one High finding: `update()` wrote without passing an
`expected` snapshot to `vibe_storage.write_text`, so two simultaneous partial
saves could lose one another's settings. The tester added a deterministic
regression case that was red (`'dark' != 'light'`). `bin/vibe_settings.py` now
captures a `read_snapshot`, passes the snapshot (or `vibe_storage.MISSING`) as
`expected`, and re-reads/re-merges the patch on `ConcurrentChangeError`, bounded
by `MAX_WRITE_ATTEMPTS = 8`. Re-verified after the fix:
`tests.unit.test_settings_storage` 25/25 OK (including the race case),
`tests.unit.test_storage` + `test_web_routes` + `test_i18n` 99/99 OK,
`tests.browser.test_settings_storage_ui` 5/5 OK, manifest check and
`verify.sh quick` Exit 0.

## Code janitor pass

A janitor run found one medium reliability defect and one low validation drift;
the remaining observations were cosmetic or out of scope. The defects were
fixed: `NV.saveSettings` now compares the **UTF-8 byte length** of the payload
with the browser keepalive limit (fallback: no keepalive), so a maximum-size
CJK favorites list is no longer silently rejected by `fetch`; and the frontend
favorite normalization now mirrors the backend's 200-character/200-item/string
rules instead of optimistically mirroring values the server drops. Both cases
were added to the browser suite and shown red in throwaway copies before the
fix. Final checks: 25/25 backend tests, 7/7 browser tests, `node --check`,
manifest check and `verify.sh quick` all green. No other janitor suggestion
was adopted: the pylint module list, the defensive import fallback and comment
wording are unchanged to keep the package scoped.
