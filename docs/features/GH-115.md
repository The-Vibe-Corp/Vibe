# GH-115 — Prioritization view on small screens

Delivery record for work package GH-115, ticket "prio view on small screen is
missing content" (`TICKET-GH-115.json`). Package branch `feature/m0p/gh-115`,
start commit `64054cd1db833f2afdb3493ef66d2e049c005373`.

## What changed

- **One explicit status precedence in the backend.** `bin/vibe_packages.py`
  defines `STATUS_PRECEDENCE = ("in-progress", "open", "blocked",
  "waiting-merge")` and the sort key `(status rank, priority P0–P8, store
  position)`. `in-progress` therefore precedes `open`/Ready regardless of
  priority; priority is only a secondary criterion inside a status group.
  `done` (Closed) is excluded and `draft` is never selected.
- **Consistent standard order and runner selection.** `priority_view()["standard"]`
  uses the same key so the view and the automatic order agree. The
  `select_package` fallback sorts its runnable candidates (`open` and
  `in-progress`) by status before priority. The `_ready()` gate is unchanged:
  `blocked` and `waiting-merge` are visible and ordered but stay unavailable
  for automatic selection until they become runnable. A deliberately saved
  `PACKAGE_ORDER` stays authoritative and is never silently re-sorted.
- **Mobile strip shows all applicable states.** `bin/web/nova-project.js`
  normalizes `ready`/`Ready` to `open`, replaces the `=== 'open'` filter with
  `NVP_IMPLEMENTATION_STATES`, and orders entries as saved order → standard
  order (now status-ranked) → remaining rows. The "prioritized ticket(s)"
  counter counts every eligible configured entry instead of Ready only.
- **Draft stays out of the implementation view.** Drafts are never implemented,
  so the mobile strip does not offer them for prioritization. They remain
  visible at the end of the backend `standard` field to preserve the existing
  GH-47 contract ("visible but not executable") and its unchanged unit test.
- **Documentation and manifest.** The living docs
  [work packages](current/work-packages.md) and [UI shell](current/ui-shell.md)
  describe the new order; `docs/import-manifest.json` carries the GH-115 entry
  with refreshed sizes and SHA-256 values. The German Trillium page is
  `89kJlya6mQai` under "Features" (see [trilium-index.md](../trilium-index.md)).

## Autonomous decisions

The ticket leaves two points open and autonomous mode forbids user questions,
so the coordinator decided: (1) the defined status order is
`in-progress → open → blocked → waiting-merge`, with `done` and `draft` excluded
from the implementation order; (2) the mobile strip excludes drafts even though
the broad wording says "all tickets except Closed", because a prioritization
strip for implementation must not offer drafts; explicitly saved
`PACKAGE_ORDER` remains binding (AP11). Both decisions are reflected in code
comments and in the living documentation.
