# GH-87 — Remove the legacy FRITZ!Box reconnect integration

Ticket: GH-87 „fritzbox reconnect entfernen" (branch `feature/m0p/gh-87`, start commit `31667f5`). The reconnect capability now lives in a separately available MCP server; Vibe itself no longer offers any router-reconnect function, UI control, documentation, or test.

## What changed

**Code and runner**
- Deleted the standalone reconnect helper and the complete reconnect block in the CLI: constants, automation/state/coordination/waiter/lock helpers, status and reconnect commands, the `fritz` CLI dispatch entry, its help text, and imports used only there (`errno`, optional `fcntl`).
- Removed the runner's reconnect hook from the error path. Quota/auth handling and retry limits remain unchanged. No CLI invocation of the installed Vibe program remains in that path.
- Removed the two web API routes (`/api/fritz` GET and POST) and all callers.

**UI**
- Removed the reconnect card from the classic environment view and the Fritzbox section from the Nova evaluations environment tab, including fetch calls, confirmation flow, status selectors and all fritz-only translation keys in both languages. In the Nova loader the harness response index was corrected after removing one `Promise.all` entry. No CSS or HTML changes were needed.

**Documentation**
- Removed the runtime-file name from the README, operating manual, user handbook, baseline inventory and diagnostics living doc; deleted the two feature records and the screenshot that described the removed feature; updated index tables and inbound links.
- Updated `docs/import-manifest.json`: removed the helper from the file set, refreshed sizes and hashes for all remaining files (70 files), and recorded this package in the change log.

**Tests**
- Deleted the three dedicated suites (two unit, one browser). Removed feature-specific methods, fixtures, selectors, file-list entries and screenshot mappings from ten mixed test modules. The quota/auth safety guard from SPEC.md is preserved in a generic form: for those failures the runner must not invoke the installed CLI at all; no reconnect-specific output markers or identifiers remain.

34 files changed: 116 insertions, 2715 deletions. `tests/` contains no fritz reference after the change.

## Scope decisions

- Historical review reports and older feature/ticket records keep their original wording as immutable audit evidence; they do not describe current behavior and no test reads them. In the import manifest, historical change-log prose is retained, while the structured `dateien` file lists were normalized to the current file set so that deleted paths are not presented as present-day files.
- `docs/baseline-installation.sha256` still lists the helper: it is a snapshot of the *active installation*, which is intentionally untouched by this package. Editing the snapshot would make `active-install.py verify` report a false "new in the active installation" finding.
- SPEC.md retains the general invariant that quota and login failures never trigger a router reconnection or manual IP lookup; it is no longer tied to a specific implementation.
- Existing installations may keep a stale helper file because setup only copies and verifies program files; adding an uninstall/migration path would reintroduce the feature name and is out of scope here.
