# F20 — PI integration: Dashboard und Anwendung mit Pi als gewähltem Harness

Stand: 2026-11-08
Ausgangscommit: `d9690e7` (F25-Review und Ticketabschluss)
Arbeitspaket: FEEDBACK.md, Eintrag F20; Projektordner-Feedback „F20 PI integration“

## Ziel

Sobald Pi als Harness gewählt ist, stellt sich die gesamte Oberfläche (und die
Anwendung) auf Pi um — ohne opencode-Formulierung und ohne opencode-Steuerung
an Stellen, die Pi nicht hat. Ohne Auswahl (Default) bleibt alles unverändert.

## Ausgangslage

Seit AP04 existiert die Harness-Schicht (`bin/vibe_harness.py`): Auswahl über
`<Zustand>/harness.json` bzw. `VIBE_HARNESS`, Diagnose, Modelllisting und
Startbefehl für opencode und Pi. Die Backend-Prüfung meldete unter

- `GET /api/server` bereits `harness` und `server_supported` (`false` bei Pi),
- `POST /api/harness` die Auswahl und das Einrichtungsvorbild,

aber die Oberfläche zeigte weiterhin an mehreren Stellen opencode an:

1. Kopfleiste: „opencode-Server: an/aus“ und Knöpfe „opencode stoppen/starten“
   — bei Pi existiert kein opencode-Server.
2. Projekt-Detail: Link „opencode-Weboberfläche“.
3. Steuerkarte (F19): Hinweis nannte die „opencode-Session“; die API
   `/api/steer` versuchte bei Pi sogar die Zustellung an den opencode-Server —
   dort endete sie je nach Kennwortlage in einer verwirrenden Fehlermeldung.
4. Subagenten-Karte (F19): neutraler Text ohne den entscheidenden Pi-Grenzwert.
5. Agenten-/Modellansicht: Aufklapper „Nicht in „opencode models““,
   Anmelde-Hinweis „( /connect bzw. opencode auth login)“ und Agentenordner-
   Hinweis ohne den Hinweis, dass Pi nur den Prompt-Text der Dateien liest.
6. Sandbox-Karte: „mit eigenem opencode-Server in bubblewrap“.
7. MCP-Tab: Anmelde-Hinweis „opencode mcp auth“.

## Fachliche und technische Entscheidungen

### Ein Informationsweg, kein Cache

Das Frontend liest die Wahl über die existierende API `/api/server`
(`harness`, `server_supported`) in jeder betroffenen Ansicht frisch
(`harnessSelected()`), nicht aus einer zweiteiligen Kopie. Damit gibt es
keine Cache-Invalidierung; die Ansicht richtet sich nach dem gespeicherten
Stand, den der Läufer ebenfalls liest. `bin/web/app.js`

- `header()`: bei Pi erscheint „Pi: Agentenläufe laufen ohne opencode-Server“;
  das Server-Steuerfeld entfällt, „Dashboard beenden“ bleibt.
- `detail()`: der opencode-Weblink erscheint nur bei serverfähiger Auswahl;
  `steerCard(name,isPi)`, `subagentCard(name,isPi)` und
  `sandboxCard(d,name,isPi)` erhalten die Wahl als Parameter.
- `agents()`: Agenten-, Profil- und Modellkarte erhalten die Wahl.

### /api/steer: verständliche Ablehnung ohne Zustellversuch

`steer_project()` in `bin/vibe-web.py` liest die Auswahl vor dem Session-Bezug.
Bei `pi` endet der Aufruf mit HTTP 400 (`error.code "rejected"`) und der
Meldung:

> Zusatzanweisungen sind bei Pi nicht möglich: Pi läuft im Print-Modus
> (--no-session) ohne fortsetzbare Session; die Anweisung kann nicht an den
> Agenten übermittelt werden.

Kein Zustellversuch, keine Protokollkennzeile. Eine unlesbare oder unbekannte
Auswahl in `harness.json` verhält sich wie bisher (opencode), damit bestehende
Installationen und ein defekter Dateifall nicht still umgeleitet werden —
 dieselbe Regel wie in `/api/server`.

### Wortlaut der Ansichten bei Pi

| Ansicht | bei Pi |
| --- | --- |
| Kopfleiste | „Pi: Agentenläufe laufen ohne opencode-Server“, kein Server-Button |
| Steuerkarte | Print-Modus-Grenze (`--no-session`, keine fortsetzbare Session) |
| Subagenten-Karte | „Bei Pi gibt es keine Subagenten-Prüfung …“ |
| Agenten-Karte | Dateien sind nur die Prompt-Quelle; Frontmatter bleibt ungenutzt |
| Profil-Hinweis | Anmeldung in Pi statt „opencode auth login“ |
| Modell-Aufklapper | „Nicht in „pi --list-models““ |
| Sandbox-Karte | „Aktiv läuft der Agent mit Pi im Print-Modus … in bubblewrap“ |
| MCP-Tab | MCP-Server werden vom Pi-Lauf nicht eingebunden |

Ohne Auswahl bleibt jeder bisherige Text und Knopf unverändert; die opencode-
Regression ist fester Teil der Browsertests.

## Grenzen

- Die Kostenverfassung ändert sich nicht: für Pi-Läufe gibt es weiterhin keine
  Kostenzuordnung (dokumentiert in docs/compatibility.md).
- Die Agentenverwaltung liest weiterhin das opencode-Dateiformat; bei Pi sind
  nur Prompt-Texte wirksam.
- MCP-Konfiguration bleibt opencode-bezogen und wird bei Pi-Läufen nicht
  eingebunden.

## Umsetzung (Branch vibe/vibe-F20-1794094233248968013-2071287-14400)

  `subagentCard()`, `sandboxCard()`, `agents()`, `profilesCard()`, `modelsCard()`,
  `mcp()`.

  aktualisiert; Änderungslog-Eintrag F20 ergänzt.
- `docs/compatibility.md`: Steuerungs- und Oberflächengrenzen von Pi ergänzt.
