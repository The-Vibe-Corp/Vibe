# GH-101 — AGENTS.md settings section rework

Delivery record for work package GH-101. Ticket: GH-101 "Ui Rework Seettings/Agents.md Section"
(branch `feature/m0p/gh-101`, start commit `abc9f94e6a356e36bfa7c63fa26e9ad2fe48824a`).

## Scope and decisions

The settings section now treats the global AGENTS.md as the primary file. Project-specific
files remain reachable through one compact native select instead of a list that grows with
the number of projects. All editing lives in the Nova edit-view sidebar.

Removed managed-block support completely from Nova UI and backend logic: no marker
constants, no split/reassembly, no marker rejection or generation remain. Existing file
bytes, including legacy marker text, are never deleted or rewritten by this change. The
byte-pinned classic UI (`bin/web/app.js`, `styles.css`, `classic.html`) cannot be edited by
contract (`tests/unit/test_ui_style_reference.py`); it keeps working through three inert
compatibility fields on the view (`before` = full text, `after` = `''`, `managed` = `null`)
and its legacy save payload, which the backend writes verbatim. No managed-block data or
logic is exposed to Nova.

Autonomous mode was active; no user question was possible. All routine decisions above were
made by the coordinating agent. Project-specific backups moved to `<project>/.vibe/agents-backups`
so they stay inside the project and unversioned; existing backups in the old state directory
are not migrated automatically.

## What changed

- **Compact selection and default.** `fillGlobalAgents` in `bin/web/nova-settings.js:397`
  renders one `select[data-nv-agents-project-select]`; the empty option is the global file.
  Every section build/route re-entry resets the selection to global; nothing is persisted.
  The former per-project rows and edit buttons are gone, so section height is independent of
  project count.
- **Sidebar editor.** One `textarea[data-nv-agents-text]` in the edit view serves both modes.
  `bin/web/nova.css` gives it `width: 100%`, `box-sizing: border-box` and a `min-width: 0`
  chain so it follows sidebar resizing without horizontal overflow.
- **Project mode preview.** `details[data-nv-agents-global-preview]` sits directly below the
  textarea, is closed by default, contains no editable field, and renders the global
  AGENTS.md as DOM nodes (headings, paragraphs, bold/italic, inline/fenced code, lists,
  blockquotes, safe links). The local renderer (`nvMarkdown` / `nvInlineNodes` /
  `nvSafeHref`, `bin/web/nova-settings.js:280-390`) never uses `innerHTML` with file content.
  The element is absent in global mode. The project settings tab likewise uses a single
  full-text field with no managed block (`bin/web/nova-project.js`).
- **Scoped backup/restore.** `agents_file_backup_dir` (`bin/vibe:2014`) is now project-local;
  `agents_file_restore(name, backup_name)` (`bin/vibe:2045`) restores exactly the named
  backup through the existing realpath containment guard and safety backup. POST
  `/api/agents_file` requires an explicit `backup` and `confirm: true` for restore; the
  global API is unchanged. A backup from another project or from the global store cannot be
  used for a project restore.
- **Managed block removed.** `agents_file_view` (`bin/vibe:1887`) returns the whole file as
  `text`; `agents_file_save(name, text, digest, before=None, after=None)` (`bin/vibe:1911`)
  writes it verbatim under digest protection, with no marker handling. Symlink refusal,
  UTF-8 errors, atomic writes and concurrent-change protection are retained.
