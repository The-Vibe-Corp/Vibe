# GH-114 — Cost overview UI improvements

Delivery record for work package GH-114, ticket "cost overview ui improvements"
(`TICKET-GH-114.json`). Package branch `feature/m0p/gh-114`, start commit
`9d72dc6c33a595b5e26c99dcdc435302e558ca19`.

The change is confined to the Nova cost view (`bin/web/nova-evals.js`), its
styles (`bin/web/nova.css`) and the import manifest. The backend, the price
storage format, the API contract and the classic interface are unchanged.
The classic UI files remain byte-identical.

## What changed

- **Compact project list.** Each project is rendered as one single-line row
  (`tr[data-nv-cost-project]`). The project name uses a dedicated
  `data-nv-cost-name` element with ellipsis truncation and the full name as a
  `title` tooltip; numeric cells do not wrap, the seven columns are retained,
  and `table-layout: fixed` plus the existing scrollable `.nv-table-wrap`
  handle narrow viewports. The decorative row marker that caused a second line
  inside the first cell is suppressed for cost rows only.
- **Monthly summary.** `div[data-nv-cost-month]` is now a bordered, flexible
  summary card with a month pill and five labelled fields
  (`data-nv-cost-month-field="sessions|input|cached|output|cost"`). Values use
  the active UI locale (`de-DE` or `en-US`) for thousands and decimal
  separators; monetary values keep four decimals and the configured currency
  symbol. The card wraps on narrow viewports instead of overflowing.
- **All models, including subagents.** The price editor collects model IDs from
  configured prices, persisted usage (`detail.models[].model`) and
  `/api/project-agents?name=…` (`agents[].effective_model`, including the
  opencode subagents `general` and `explore`). Models are de-duplicated by ID,
  so one `div[data-nv-price-row]` exists per model. Agent/role badges
  (`data-nv-price-agent`) come from usage and agent configuration; existing
  prices remain pre-filled and editable.
- **Currency fields and validation.** Price inputs are text fields with
  `inputmode="decimal"` and locale-formatted initial values including the
  configured currency. A tolerant parser accepts plain `1.5`, German
  `1,50 €`/`1.234,50 €` and English `$1,500.50` forms (last separator is the
  decimal separator), currency codes and non-breaking spaces. Empty, negative
  and non-numeric values show the existing error element and prevent the POST.
  When USD is configured, displayed values are converted back to the stored
  EUR base price with `usd_rate`. A visible hint states currency and rate.
- **Translations and manifest.** New German source strings have English
  translations in the existing `VIBE_I18N.extend` block of `nova-evals.js`.
  `docs/import-manifest.json` has a GH-114 change entry with refreshed size and
  SHA-256 for the two changed web files.

## Verification

Environment: isolated package worktree, temporary HOME/VIBE state, dedicated
loopback ports, local headless Chromium. No production instance, no model calls
and no functional MCP calls. All checks were run on the final code state.

- Test-first evidence: the independent tester added five browser cases to
  `tests/browser/test_activity_ui.py` (`CostsOverviewUiTest`) and ran them on
  the pristine start commit: `Ran 5 tests — FAILED (failures=13, errors=4)`.
  Failures were the intended missing hooks, locale formats, subagent models and
  numeric-only price inputs. Full report:
  [GH-114 test report](../reviews/GH-114-test-report.md).
- Review-driven red/green: review 1 required a fix for locale-aware thousands
  grouping; the new de-DE/en-US cases initially failed with
  `1234 != 1.234 within 6 places` and pass after the parser fix. The USD
  no-drift case was likewise red (`0.1234 != 0.1233613445…`) before its fix.
- Focused green: all eight cases `Ran 8 tests — OK` on the final state.
- Static checks: `node --check bin/web/nova-evals.js` → OK;
  `bash scripts/verify.sh package` → exit 0 (manifest 70/70, syntax and secret
  checks green). `tests.unit.test_ui_style_reference` confirms the classic UI
  files are unchanged.
- Full run: `bash scripts/verify.sh full` without flags → exit 7 solely because
  the worktree's `VERIFY_ENV=head_of_vibe` has no committed baseline section;
  GH-108 and GH-109 document the same configuration caveat. With the committed
  baseline environment (`--env pi-aarch64-py3.14-namespaces`): 2762 tests,
  15 failed modules. A control `git archive` of the untouched start commit
  `9d72dc6` under the same environment produced 17 failed modules; all 15 final
  modules are part of that control set, so no new failing module was introduced.
  The four signatures reported as new relative to the committed baseline are
  byte-identical to those documented at the untouched start commit in GH-108/
  GH-109. `test_run_autostop` is intermittent under parallel full runs and passes
  in isolation (`Ran 2 tests — OK`); it is already listed as known red in that
  baseline environment. No baseline, threshold, gate command or permission was
  changed.
- Baseline: `CostsTest.test_costs_missing_price_editor_save_updates` and two
  further `CostsTest` cases are already red at the start commit because the F34
  fixture inserts only a live `opencode.db` session while GH-99 reads persisted
  package usage. These tests were not changed. The GH-114 case uses a stateful
  `/api/costs` stub so the parser and display contract is covered without that
  fixture.
- Browser verification covers 1400 px and 900 px viewports; no mobile-device
