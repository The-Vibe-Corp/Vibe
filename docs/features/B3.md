# B3 — Nachricht an Agent senden wirft Fehler (Kennwortdatei automatisch)

Stand: 2026-11-08
Ausgangscommit: `eb05351` (`F24: Ausgabemaske zeigt aktiven Agenten und Agent-Tabs`)
Arbeitspaket: FEEDBACK.md, Eintrag B3

## Bug

```
- [ ] B3 Nachricht an Agent senden wirft fehler
  Art: Bug
  Beschreibung: Der opencode-Server ist nicht für Zusatzanweisungen angemeldet
  (Kennwortdatei fehlt). dies sollte automatisch konfiguriert sein.
```

## Ursachenanalyse

Das Senden einer Zusatzanweisung aus dem Dashboard (`POST /api/steer`, F19)
liest das Basic-Auth-Kennwort aus `<runtime>/opencode.password` und verweigert
die Zustellung mit „Der opencode-Server ist nicht für Zusatzanweisungen
angemeldet (Kennwortdatei fehlt)“, wenn die Datei fehlt oder leer ist
(`bin/vibe-web.py`, `opencode_password()` und `steer_project()`).

Die Datei wurde bisher ausschließlich von einem einzigen Einstiegspunkt
angelegt: `vibe server start` ruft `ensure_opencode_password()` auf
(`bin/vibe`). Alle übrigen Wege zu einem laufenden Agenten haben sie nicht
eingerichtet:

- `vibe run` (CLI) und der Laufstart aus dem Dashboard (`POST /api/run`)
  münden beide in `bin/vibe`, `cmd_run()` — ohne Anlage der Kennwortdatei.
- Ein Agentenlauf, der den gemeinsamen opencode-Server erreicht
  (`vibe-run.sh`, `server_is_up()`), verbindet sich damit; die Sitzung des
  Agenten liegt dann dort. Erst beim Senden aus dem Dashboard erfuhr der
  Nutzer, dass die Anmeldung nie eingerichtet worden war.
- In der beobachteten Installation (`$VIBE/_logs`) fehlte die Datei
  vollständig; der gemeinsame opencode-Server lief dort nicht unter
  vibe-Verwaltung, sondern als eigenständiger `opencode serve --service`
  ohne `OPENCODE_SERVER_PASSWORD`. Damit ließ sich die F19-Anmeldung
  grundsätzlich nicht zustellen, und die Nutzerin/der Nutzer sah keine
  Richtung, aus der die Konfiguration automatisch kommen sollte.

## Entscheidung

Die Kennwortdatei wird beim **Laufstart** automatisch eingerichtet — am
einzigen Einstiegspunkt aller Agentenläufe:

- `bin/vibe`, `cmd_run()`: unmittelbar nach der Agentenauswahl und vor der
  Laufregistrierung ruft der Laufstart `ensure_opencode_password()` auf.
  Die bestehende Funktion (F19) bleibt unverändert: Es wird nur ein
  Zufallskennwert (`secrets.token_urlsafe(24)`) angelegt, wenn die Datei
  fehlt oder leer ist; Modus `0600`, soweit das Dateisystem Rechte trägt
  (FUSE/NTFS-Toleranz). Eine vorhandene, nichtleere Datei wird nicht neu
  gerollt (AK2).
- Ein Anlagefehler (z. B. schreibgeschützte Laufzeit) bricht den Laufstart
  mit der verständlichen Meldung von `ensure_opencode_password()`
  („opencode-Kennwort konnte nicht angelegt werden …“) ab, statt später
  still bei der Zustellung zu scheitern.
- `steer_project()` in `bin/vibe-web.py` bleibt unverändert: Es verweigert
  weiterhin die Zustellung, wenn die Datei tatsächlich fehlt oder unlesbar
  ist, und meldet Serverablehnungen unverändert (HTTP 401/5xx). Die
  F19-Semantik (Erfolg nur bei gültiger Basic-Auth und 2xx) bleibt bestehen.
- Kein Caching, keine neuen Dateien, keine neuen Abhängigkeiten; die
  Kennwortdatei ist und bleibt eine Laufzeitdatei (`$VIBE_RUNTIME`), nie im
  Repository.

KISS-Begründung: Der Laufstart deckt jeden Weg zu einem laufenden Agenten
ab (CLI, Dashboard, autonome Läufe), weil alle über `cmd_run()` führen.
Der frühe Anlagezeitpunkt stellt sicher, dass jede Sitzung, die der Lauf
erzeugt, von einer eingerichteten Anmeldung begleitet ist.

## Grenzen (ehrlich benannt)

- Läuft ein gemeinsamer Server bereits, der ohne die Kennwortdatei
  gestartet wurde (etwa von Hand oder von einer älteren Installation),
  „richtet“ die automatisch erzeugte Datei ihn nicht nachträglich ein.
  opencode erzwingt die Anmeldung nur, wenn es beim Serverstart die
  Kennwortdatei erhalten hat; ein Server ohne `OPENCODE_SERVER_PASSWORD`
  nimmt die Zusatzanweisung trotzdem an, ein Server mit anderem Kennwort
  antwortet mit HTTP 401. Beides ist der bestehende F19-Fehlerpfad mit
  klarer Meldung, keine B3-Regression. Empfehlung: `vibe server stop &&
  vibe server start`, damit der verwaltete Server mit der automatisch
  angelegten Anmeldung startet.
- Unter Sandbox (`SANDBOX=on`) und bei Harness Pi gilt die bestehende
  F19/F20-Semantik weiter (Standalone-Server bzw. keine fortsetzbare
  Session); B3 ändert daran nichts.
