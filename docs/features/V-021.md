# V-021 — Installationsvollständigkeit und Aufräumregeln

Stand: 2026-11-02
Ausgangscommit: `f245113`
Arbeitsbranch: `fix/installer-autonomous-module`

## Ziel

Nach einer Aktualisierung der produktiven Installation startete `vibe` nicht
mehr:

```
ModuleNotFoundError: No module named 'vibe_autonomous'
```

Ursache war die Liste `PROGRAM_FILES` im Setup. Sie enthielt mehrere vom
Startbefehl importierte Module nicht, darunter `vibe_autonomous.py`. Ein
Update kopiert nur die dort genannten Dateien; die Installation blieb dadurch
unvollständig, obwohl der Setup erfolgreich meldete.

Zusätzlich gilt ab diesem Arbeitspaket eine allgemeine Aufräumregel für alle
vibe-Projekte: Projektordner enthalten nur Quellcode, Konfiguration, Tests und
vereinbarte Nachweise. Temporäre Dateien, Protokolle, Sicherungen und
Arbeitskopien werden nach dem Arbeitspaket entfernt und nicht committet.

## Fachliche Umsetzung

### Vollständige Programmliste

`PROGRAM_FILES` enthält jetzt jedes Modul, das `bin/vibe` beim Start aus dem
eigenen Ordner importiert:

- `vibe`, `vibe-run.sh`
- `vibe_runs.py`, `vibe-web.py`
- `vibe_mcp.py`, `vibe_opencode.py`, `vibe_models.py`
- `vibe_sandbox.py`, `vibe_paths.py`, `vibe_storage.py`
- `vibe_guide.py`, `vibe_questions.py`, `vibe_autonomous.py`
- `fritz-reconnect.py`

Damit installiert ein Update auch das zuvor fehlende Modul. Die Liste ist
keine unabhängige Wunschliste mehr: Ein Regressionstest liest die Importe aus
`bin/vibe`, prüft jedes vorhandene Geschwistermodul gegen `PROGRAM_FILES` und
startet anschließend die frisch installierte CLI mit `vibe types`.

### Aufräumregeln für alle Projekte

Die Regel steht als verwalteter Block in allen mitgelieferten
Projektvorlagen (`templates/*/AGENTS.md`) und zusätzlich ausführlicher in der
`AGENTS.md` dieses Repositorys:

```
<!-- vibe:general-rules -->
## Projektordner sauber halten
...
<!-- /vibe:general-rules -->
```

`vibe init` ergänzt den Block in einer bereits vorhandenen `AGENTS.md`, wenn
der Marker fehlt. Vorhandene Inhalte bleiben unverändert; ein zweiter Aufruf
ergänzt nichts. Symlinks werden nicht verfolgt, damit nichts außerhalb des
Projekts geschrieben wird. `vibe new` ruft dieselbe Absicherung auf.

## Technische Umsetzung

| Datei | Änderung |
| --- | --- |
| `scripts/setup-vibe.py` | `PROGRAM_FILES` um alle Startmodule ergänzt, insbesondere `vibe_autonomous.py` |

## Grenzen

- Die Prüfung liest die Importe nur aus `bin/vibe`. Importiert ein künftiges
  Modul ausschließlich aus `vibe-web.py` oder einem anderen Einstieg, muss die
  Liste weiterhin bewusst gepflegt werden.
- `vibe init` ergänzt die Aufräumregeln nur bei einem Aufruf. Bereits
  vorbereitete Projekte erhalten sie erst, wenn `vibe init` erneut läuft.
- Der verwaltete Block wird nicht automatisch entfernt oder inhaltlich
  aktualisiert; eine spätere Änderung der Regeln benötigt eine neue
  Kennung oder einen eigenen Migrationsschritt.

## Prüfbefehle

```
python3 -m unittest tests.unit.test_setup_vibe -v
python3 -m unittest tests.unit.test_project_management -v
bash scripts/verify.sh quick
bash scripts/verify.sh full
```
