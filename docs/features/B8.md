# B8 — Projekt öffnen blockiert bei nicht erreichbarem Git-Remote

Stand: 2026-11-10
Art: Bug
Arbeitsbranch: `feature/b8-projekt-oeffnen-ohne-remote`

## Symptom

Das Dashboard öffnet ein Projekt nicht mehr. Im Browser bleibt
`GET /api/project?name=...` ohne Antwort; die Rückfragen-Abfrage läuft
weiter. Bei einem Projekt mit nicht erreichbarem `origin` (z. B. kein
Netzwerk, VPN aus, GitHub nicht erreichbar) antwortet die Projektansicht
erst nach dem Git-Timeout von 120 Sekunden oder gar nicht.

## Ursache

`vibe_services.project_detail` rief für die Karte „Git & GitHub“
`vibe_github.status()` und `vibe_github.branches()` auf. Beide lesen
Ahead/Behind über `git ls-remote` vom Remote. Das geschah auch dann, wenn
GitHub im Projekt gar nicht aktiviert war (`GITHUB_ENABLED` fehlt). Der
synchron aufgerufene Netzwerkzugriff blockierte damit die gesamte
Projektansicht.

## Änderung

- `vibe_github.status(path, remote=False)` und
  `vibe_github.branches(path, remote=False)` lesen Ahead/Behind
  ausschließlich aus der lokalen `origin/<branch>`-Referenz. Es findet
  keine Netzwerkabfrage statt.
- Ohne aktivierte GitHub-Verknüpfung wird auch im normalen Modus
  (`remote=True`) nie ein Remote kontaktiert.
- `vibe_services.project_detail` nutzt für die Projektansicht den
  lokalen Modus. Das Öffnen eines Projekts wartet damit nie auf ein
  Remote.
- Git-Aufrufe laufen mit `GIT_TERMINAL_PROMPT=0` und
  `GCM_INTERACTIVE=never`; reine Fern-Leseabfragen haben ein kurzes
  Zeitlimit von 10 Sekunden statt 120 Sekunden. Bewusste Aktionen
  (`fetch`, `pull`, `push`) behalten das bisherige Zeitlimit.

Bewusste Aktionen aus der GitHub-Karte (Abrufen, Pull, Push, Issues,
Merge-Request) bleiben unverändert Netzaktionen und werden weiterhin nur
durch einen Klick ausgelöst. Die Karte zeigt nach einem Abruf den dann
aktuellen lokalen Referenzstand.

  `branches` — ca. 0,1 s, Exit 0.

## Grenzen

Die Karte zeigt beim ersten Aufbau den lokalen Referenzstand. Der aktuelle
Fernstand wird erst durch „Abrufen (fetch)“ aktualisiert. Das ist der
bewusste Kompromiss, damit die Projektansicht nicht auf das Netzwerk
wartet. Die GitHub-Schaltflächen selbst (Authentifizierung, Token,
Fehlermeldungen) sind Gegenstand von B7 und nicht Teil dieses Fixes.
