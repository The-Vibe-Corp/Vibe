# V-025 — Ungültigen Startagenten aus der Projektauswahl beheben

Stand: 2026-11-08
Ausgangscommit: `ee20120`
Arbeitsbranch: `feature/v-025-agent-start-repair`

## Ziel

Ein Projektstart darf nicht an einem veralteten `AGENT`-Eintrag in
`.vibe/project.env` scheitern, wenn das Projekt bereits einen gültigen
Vibe-Agenten definiert hat. Vibe erkennt den ungültigen Eintrag, verwendet
einen im Projekt verfügbaren und aktiven Agenten und korrigiert die
Projektdatei.

Auslöser war ein Projekt, dessen `AGENT` nach einer Agentenumemnennung auf
einen nicht mehr vorhandenen Namen zeigte. Der Start brach mit
„Agent … ist für dieses Projekt nicht ausgewählt oder nicht konfiguriert“ ab,
obwohl der projektweite Vibe-Agent vorhanden und aktiv war.

## Fachliches Verhalten

### Start mit gespeichertem Agenten

Vibe prüft den in `.vibe/project.env` gespeicherten `AGENT` vor dem Start:

- Ist der Agent systemweit vorhanden und im Projekt aktiv, wird er
  unverändert verwendet. Die Projektdatei bleibt unverändert.
- Ist der Agent systemweit nicht vorhanden oder im Projekt nicht aktiv, fällt
  Vibe auf den projektweiten Vibe-Agenten zurück. Voraussetzung ist, dass
  dieser systemweit vorhanden, im Projekt aktiv und mit einem Modell
  konfiguriert ist.
- Vibe schreibt den Ersatzagenten als `AGENT` in `.vibe/project.env`. Dabei
  wird ausschließlich die `AGENT`-Zeile ersetzt; alle anderen Zeilen,
  Kommentare und Zeilenenden bleiben erhalten.
- Die Ausgabe nennt den veralteten und den neu verwendeten Agenten.

### Ausdrücklich übergebener Agent

Ein per CLI übergebener Agent (`vibe run <projekt> <agent>`) wird nicht
automatisch ersetzt. Ist er im Projekt nicht aktiv, bleibt die bisherige
Ablehnung mit verständlicher Meldung erhalten. Die Projektdatei wird dabei
nicht verändert.

### Schreibfehler

Kann die Korrektur von `.vibe/project.env` nicht geschrieben werden, startet
der Agentenlauf trotzdem mit dem ermittelten Vibe-Agenten. Der Schreibfehler
wird gemeldet; der Lauf wird nicht abgebrochen.

### Projektvorlagen

Die mitgelieferten Vorlagen unter `templates/*/.vibe/project.env` enthalten
keinen fest eingebauten `AGENT`-Namen mehr. Neue Projekte verwenden damit den
konfigurierten Vibe-Agenten und benötigen beim ersten Start keine Korrektur.
Bestehende Projekte mit einem alten Eintrag werden beim Start repariert.

## Technische Umsetzung

### `bin/vibe`

- `cmd_run` liest den gespeicherten `AGENT` und prüft ihn gegen
  `project_agent_inventory(name)` (systemweite Agenten) sowie die aktive Liste
  aus `project_agents_load(name)`. Der Vibe-Agent gilt dabei immer als aktiv,
  weil `run_agent_selection` ihn ebenfalls ergänzt.
- Nur wenn kein Agent ausdrücklich als Argument übergeben wurde, darf der
  gespeicherte Wert automatisch ersetzt werden.
- `repair_project_agent(name, agent)` ersetzt oder ergänzt genau die
  `AGENT`-Zeile. Die Datei wird über `vibe_storage.write_text` mit erwarteter
  Prüfsumme geschrieben; eine gleichzeitige Änderung wird dadurch nicht still
  überschrieben.
- Der Ersatz wird unquoted als `AGENT=<name>` geschrieben, damit die
  bestehende, von Hand gepflegte Projektdatei ihr Format behält. CRLF und LF
  werden beibehalten.
- Die Ausgabe verwendet die vorhandene Farbausgabe und ist damit auch im
  Dashboard-Lauf sichtbar.

### Vorlagen und Importmanifest

- `AGENT=coding-agent_deepseek` wurde aus allen sechs Vorlagen entfernt.
- `docs/import-manifest.json` enthält die neuen Prüfsummen und einen
  begründeten Änderungseintrag für V-025.

## Tests

Die Tests stammen vom unabhängigen Test-Agenten
(`tests/unit/test_v025_agent_start_repair.py`, 11 Tests). Einzelheiten und
Rot-/Grün-Nachweis stehen in `docs/reviews/V-025-test-agent-report.md`.

Abgedeckt sind:

- nicht vorhandener `AGENT` → Start mit Vibe-Agent und Korrektur der Datei,
- global vorhandener, aber im Projekt nicht aktiver `AGENT` → gleiches
  Verhalten,
- Erhalt aller anderen Zeilen und Kommentare,
- Erhalt von CRLF-Zeilenenden und Ersetzung eines gequoteten `AGENT`-Werts,
- unveränderte Verwendung eines gültigen, aktiven Agenten,
- Ablehnung eines ausdrücklich übergebenen, nicht aktiven Agenten ohne
  Schreibzugriff,
- Start trotz Schreibfehlers mit Meldung,
- Ausgabe mit altem und neuem Agentennamen,
- keine `AGENT`-Zeile in den mitgelieferten Projektvorlagen,
- ungültige Agentennamen werden von `repair_project_agent` ohne Schreiben
  abgelehnt.

## Grenzen

- Die Korrektur gilt nur für systemweite Agenten. Projektlokale Agenten werden
  gemäß AP03 nicht als Projektauswahl verwendet.
- Ein ausdrücklich übergebener Agent wird nicht automatisch korrigiert.
- Es wird nur die `AGENT`-Zeile repariert; weitere veraltete Einträge in
  `project.env` bleiben unangetastet.
- Die produktive Installation unter `$VIBE/_toolchain` wurde in diesem
  Arbeitspaket nicht überschrieben. Die Änderung wirkt nach der nächsten
  vorgesehenen Installation bzw. Aktualisierung.

## Offene Punkte

- Kein gesonderter Hinweis in der Weboberfläche vor dem Start; die Korrektur
  wird beim Start ausgegeben. Eine vorbeugende Anzeige im Projektdetail wäre
  ein mögliches Folgepaket.
- Akzeptierter Review-Minor aus Runde 2: `NAME_RE` ist mit `$` verankert und
  lässt in Python einen abschließenden Zeilenumbruch durch. Über die
  Oberfläche ist kein solcher Rollenname erreichbar; die Umstellung auf
  `fullmatch` ist als kleine Härtung für ein Folgepaket vorgemerkt.
