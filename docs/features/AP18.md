# AP18 — Kennwort der WebUI über die CLI setzen

## Ziel

Das Anmeldekennwort des Dashboards lässt sich bisher nur im Dashboard selbst
setzen (Karte „Zugriffssicherheit“). Wer das Kennwort vor dem ersten Start,
aus einem Skript oder ohne offene Browser-Sitzung setzen oder entfernen will,
hatte keinen vorgesehenen Weg. AP18 ergänzt den CLI-Zugang über den bestehenden
Dashboard-Befehl: `vibe ui password …`.

## Umfang / Änderungen

`bin/vibe`:

* Neuer Unterbefehl unter `vibe ui`:
  * `vibe ui password set` — liest das Kennwort interaktiv zweimal über
    `getpass` (Eingabe bleibt unsichtbar); abweichende Wiederholung bricht ab,
    ohne die Datei zu ändern.
  * `vibe ui password set --stdin` — für Skripte: liest genau eine Zeile
    (mit oder ohne abschließenden Zeilenumbruch) von der Standardeingabe.
  * `vibe ui password clear` — entfernt den Kennwort-Hash; ohne vorhandenen
    Hash bleibt die Datei unverändert (Exit 0, verständliche Meldung).
  * `vibe ui password status` (und `vibe ui password` ohne Unteraktion) —
    zeigt, ob ein Kennwort gesetzt ist, ohne Hash-Details offenzulegen.
* Kennwörter sind nie Kommandozeilenargumente (Prozessliste und
  Shell-History); ein solcher Aufruf wird mit einer Hinweismeldung abgelehnt.
  Das entspricht dem bestehenden Muster von `vibe github <p> token` (B7/AP9).
* Nicht-interaktives `set` ohne `--stdin` wird abgelehnt statt zu hängen.
* Die Fachlogik bleibt vollständig in `bin/vibe_ui_config.py`
  (`set_password`/`clear_password`/`load`): Mindestlänge 8, atomares
  Schreiben, gesalzener PBKDF2-Hash, kein Klartext in ui.json. CLI und Web
  nutzen dieselbe Prüfung (V-019: CLI/Web nutzen dieselbe Fachlogik).

`bin/vibe-web.py`:

* `POST /api/login` liest ui.json vor der Kennwortprüfung neu
  (`reload_ui_data()`). Eine per CLI (oder von Hand) geänderte Datei wirkt
  damit im laufenden Betrieb ohne Neustart; Allowlist-Änderungen derselben
  Quelle ebenfalls. Bleibt die Datei dabei defekt, bleibt der zuletzt
  geladene Stand wirksam (die Funktion ersetzt nichts still durch Defaults).
* Das Instanz-Token und die Session-Cookie-Mechanik bleiben unverändert.

`docs/import-manifest.json`:

* Neuer Änderungseintrag AP18; Größe/SHA-256 von `bin/vibe` und
  `bin/vibe-web.py` aktualisiert und begründet.
* Vorbestehende Manifest-Defekte mitkorrigiert, weil sie jede Prüfung
  (`check-import-manifest.py`, `verify.sh quick`) als JSONDecodeError
  blockierten:
  1. fehlendes Komma zwischen den Änderungseinträgen AP17 und B14
     (seit dem AP17-Merge auf `dev`).
  2. veraltete Doppelfassung im `files`-Eintrag von `bin/vibe`
     (stale `bytes/path/sha256`-Felder innerhalb desselben Objekts).

## Abgrenzung

* Keine Änderung an `start`/`stop`, `--port`, `--bind` oder dem
  Kompatibilitätsaufruf `cmd_ui(<string>)`.
* Kein neues Modul, keine neuen Abhängigkeiten (Standardbibliothek only).
* Kein automatischer Neustart des Dashboards; nicht nötig, weil die Anmeldung
  ui.json neu liest. Offene Browser-Sitzungen bleiben gültig (Logout beendet
  sie bewusst).

## Grenzen und Hinweise

* Die interaktive Eingabe erwartet ein Terminal; Skripte nutzen `--stdin`.
* „Ohne Echo“ wird über die PTY-Ausgabe der Tests geprüft, nicht über
  termios-Flags. In dem schmalen Sonderfall, dass die Standardeingabe ein
  TTY bleibt, aber kein steuerndes Terminal erreichbar ist (z. B.
  `setsid` mit tty-stdin), fällt `getpass` intern auf lesende Eingabe mit
  Echo zurück (GetPassWarning) — die Unsichtbarkeit ist dann nicht
  gewährleistet (Reviewrunde 1, Minor).
* Wer ein laufendes Dashboard mit bereits geöffneten Sitzungen hat, muss sich
  dort abmelden, um das neue Kennwort zu verwenden; Zwangs-Abmeldung aller
  Sitzungen bei Kennwortwechsel ist bewusst nicht implementiert.
* FUSE/NTFS: Unix-Rechte 0600 auf ui.json sind best effort (bestehendes
  Verhalten von `vibe_ui_config.save`, unverändert).
