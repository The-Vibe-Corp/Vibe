# GH-122 — Web UI fails to start after update

Delivery record for bug ticket GH-122, "Web UI fails to start after update:
vibe_settings.py missing from installation" (GitHub issue #122). Work was done
on `dev`; no production installation was modified.

## Symptom

After updating an installation to the GH-117 state (`8d8c89a`, version
0.18.0), the dashboard no longer started. The installed `vibe-web.py` exited
immediately with:

```
ModuleNotFoundError: No module named 'vibe_settings'
```

The failure was reproduced with the installed toolchain under an isolated
temporary `HOME`, `VIBE`, state, and runtime directory. The running production
installation was not started, stopped, or updated.

## Root cause

GH-117 added `bin/vibe_settings.py` and made `bin/vibe-web.py` import it at
module load time. `scripts/setup-vibe.py` installs program files from the
explicit `PROGRAM_FILES` list, but that list was not extended with the new
module. An update therefore copied the new `vibe-web.py` without the module it
needs, even though the setup reported success.

This is the same class of defect as V-021 (`vibe_autonomous.py`), whose guard
only inspected imports of the CLI entry point `bin/vibe`, not the dashboard
entry point `bin/vibe-web.py`.

## What changed

- **Install set completed.** `scripts/setup-vibe.py` now lists
  `vibe_settings.py` in `PROGRAM_FILES`, so install, update, rollback, and
  uninstall handle the module like every other program file.
- **Regression coverage for both entry points.** The independent tester
  extended `tests/unit/test_setup_vibe.py`:
  - `test_program_files_cover_all_shipped_program_files` compares every
    regular file in `bin/` with `setup.PROGRAM_FILES`, so a future program
    module cannot be omitted silently.
  - `test_every_module_imported_by_the_installed_entry_points_is_installed`
    derives sibling imports from both `bin/vibe` and `bin/vibe-web.py` and
    checks them against the install set.
  - `test_installed_web_entry_point_starts_without_missing_modules` installs
    the real repository into a temporary toolchain and starts the installed
    dashboard on a dedicated loopback port. It waits for `/api/health`, checks
    the app identity and port, and fails explicitly on
    `ModuleNotFoundError`.
  - The test-local `PROGRAM_FILES` mirror was extended with
    `vibe_settings.py` so the installation fixture represents the full
    program set.
- **Manifest and living documentation.** `docs/import-manifest.json` carries
  the refreshed size and SHA-256 of `scripts/setup-vibe.py` plus the GH-122
  change entry. The installation documentation records the entry-point
  coverage contract.

## Repairing an affected installation

Re-running the normal setup update with the corrected source copies the
missing module:

```bash
./install-vibe.sh
```

or, with an explicit source:

```bash
python3 scripts/setup-vibe.py --update --vibe "$VIBE" --source "$KIT"
```

The update keeps projects, runtime data, personal configuration, and backups.
No manual file copy is required.

## Post-review correction

Review round 1 (`docs/reviews/GH-122-review-1.md`) returned
`CHANGES REQUIRED` for one Medium finding: the second test-side
`PROGRAM_FILES` mirror in `tests/unit/test_install_lifecycle.py` had not been
updated. The tester added only `"vibe_settings.py"` to that mirror; the
pre-existing omissions of `vibe_keys.py` and `vibe_tickets.py` were left
untouched as separate baseline debt.

Re-verified after the correction:

- `python3 -m unittest tests.unit.test_install_lifecycle tests.unit.test_setup_vibe`
  → `Ran 138 tests`; all 57 failures/errors remain in
  `test_install_lifecycle` with the committed baseline signatures
  (`setup_vibe_b17.SetupError` / `sha256:320f89d7…` and the restored
  `AssertionError`); `test_setup_vibe` is
  67/67 OK. No new failure signature.
- `bash scripts/verify.sh quick` → Exit 0.
- `bash scripts/verify.sh package` → Exit 0.
- Final `bash scripts/verify.sh full --env pi-aarch64-py3.14-namespaces` →
  the same 14 failed modules and the same five stale-baseline signatures as
  before the correction; no GH-122-specific regression.

The two optional documentation notes from the review (manifest file count and
status dates) were also corrected.
