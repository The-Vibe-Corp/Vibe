# GH-82 — Closed tickets below the board, runner-owned states

Ticket: GH-82 „Zuordnung geschlossene Tickets in Board fehlerhaft“ (branch
`feature/m0p/gh-82`, start commit `cdf0197`). The change fixes the Nova work
view, removes user-facing controls for runner-owned ticket states, aligns the
Nova dropdown style, and restricts the web ticket API to `draft`/`open`.

## What changed

**Completed tickets outside the board.** `nvpWorkView` now splits the ordered
tickets into open and done items. `nvpWorkBoard` (desktop) and `nvpWorkList`
(mobile) receive only the open items, so a done ticket never lands in the
`ready` column any more. Done cards render in a dedicated grid
(`[data-nv-work-done-grid]` with cards in `[data-nv-work-done-cards]`) that
follows the board or the mobile list and has the heading `Abgeschlossen`
(EN `Completed`). `nvpColOfState` returns `done` for done rows instead of
`ready`. The grid container is always rendered (empty and hidden when no done
card is visible), so `nvpSyncCardState` can move a card that becomes `done`
into it and remove its `draggable` attribute. Done cards keep the same
`data-nv-ticket`, `data-nv-state`, `data-nv-kind`, and detail hooks as before.
Copying a done card passes the full ordered ticket list to the editor, so the
suggested ID is not an already-used ID from the done subset.

**No manual control for runner-owned states.** The Nova detail panel offers
`select[data-nv-ticket-state-select]` only while the ticket is `draft` or
`open`. For `in-progress`, `blocked`, and `waiting-merge` it shows the
read-only notice `Zustand wird vom Läufer gesetzt` (EN `Status is set by the
runner`) instead; `done` keeps its existing evidence notice. The `ticket-close`
button was removed from the detail and the editor, the `package-close` button
was removed from the detail, and the now-unused `nvpConfirmClose()` helper was
deleted. Details, edit, delete, ready/draft, resume, and copy actions are
unchanged. The classic `app.js` creation forms (`ticketStateSelect()`) also
offer only `draft`/`open` with default `open`, and the classic ticket card no
longer renders `Paket abschließen`/`/api/package action=close`; the backend
endpoint remains for the runner.

**Backend.** `WEB_TICKET_STATES` is `("draft", "open")`.
`POST /api/ticket action=close` is rejected with `ok:false` and a clear
message without changing the ticket state. Internal `vibe_tickets.close`,
`vibe.package_close`, and `/api/package action=close` remain available for the
runner and the merged-PR path.

**One Nova dropdown style.** `bin/web/nova.css` defines a single native select
rule under `[data-nv-app] select` (width, border, radius, surface, text,
padding, font). The duplicate select declarations were removed from the
`.nv-card` form rule, so the detail select and a form select compute identical
border, padding, background, color, and font. The `.nv-combobox` widget and
the classic stylesheet are unchanged.
